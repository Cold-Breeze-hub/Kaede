## 1. 架构目标

| # | 目标 | 由哪条需求倒逼 |
| --- | --- | --- |
| A1 | **界面与原型 1:1 可对齐** | 定稿是 CSS 级约束（6 列 `minmax`、`mask-image` 渐隐、五条转场曲线、`grid.top` 前后相等）。任何不能写标准 CSS 的方案直接出局 |
| A2 | **内核与界面解耦** | 源站会变、播放内核可能换（P1 上 mpv），界面不能跟着改 |
| A3 | **单源失败不传染** | FR-SRC-03/04：10 个源并发，一个超时不能拖垮整页 |
| A4 | **数据只有一处真相** | FR-NAV-01 + §6.3：地址即状态、进度不丢、迁移可控 |
| A5 | **两人并行不打架** | `06-开发规范.md`：目录级所有权 + 契约先行 |
| A6 | **不引入服务端** | C1：单机自用，装完即用，没有后端可运维 |

## 2. 为什么不能是纯前端

原型现在是四个静态文件，但正式版有六件事浏览器做不了：

| 能力 | 浏览器 | 必须在内核 |
| --- | --- | --- |
| 写任意磁盘路径 / 认盘符容量 | ✗ | ✓ |
| 启动本地 EXE（游戏） | ✗ | ✓ |
| 改写请求头（Referer/UA/Cookie）绕源站防盗链 | ✗（CORS 挡住） | ✓ |
| HLS 分片合并、断点续传、整季队列 | 勉强但不可靠 | ✓ |
| SQLite 事务与全文检索 | ✗（IndexedDB 不够） | ✓ |
| 嵌入 libmpv（Anime4K / 多音轨 / 外挂字幕） | ✗ | ✓ |

结论：**渲染层继续用 Web 技术（保住 A1），能力层放到本地进程（满足 A2–A4）**。这不是"选个框架"，是"必须两层"。

## 3. 分层

```
┌──────────────────────────────────────────────────────────────┐
│  L4  视图层（渲染进程 / WebView）                              │
│      路由 · 页面 · 组件 · 设计令牌 · 动效                       │
│      只有 DOM 与状态，没有任何文件/网络/数据库权限               │
└───────────────────────────┬──────────────────────────────────┘
                            │  受控 IPC（白名单通道 + 结构化类型）
┌───────────────────────────┴──────────────────────────────────┐
│  L3  应用服务层（主进程 / 内核）                                │
│      SourceEngine · Library · Player · Reader · Download       │
│      Resource · Scraper · Search · Settings · Diagnostics      │
│      每个服务只暴露 `04` 里定义的接口，互相不直接摸对方内部       │
└───────────────────────────┬──────────────────────────────────┘
┌───────────────────────────┴──────────────────────────────────┐
│  L2  领域能力层                                                │
│      规则解析 · 选择器引擎 · 选源打分 · HLS 代理 · 分段下载      │
│      命名模板 · 目录扫描 · 节流器 · 派生计算（progress/时长）     │
└───────────────────────────┬──────────────────────────────────┘
┌───────────────────────────┴──────────────────────────────────┐
│  L1  基础设施层                                                │
│      HTTP（代理/重试/限速） · SQLite（WAL） · FS · 子进程       │
│      libmpv sidecar · 日志 · 时钟/定时器                        │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向单向向下**。L2 不许知道 L3 存在；L1 不许 import 任何业务类型。

### 3.1 两种外壳的映射（技术选型未定时两边都成立）

| 概念 | Electron | Tauri 2 |
| --- | --- | --- |
| 视图层 | Renderer（Chromium 自带） | WebView（系统 WebView2） |
| 内核 | Main process（Node 24） | Rust core |
| 桥 | `contextBridge` + `ipcMain.handle` | `invoke` + command |
| 数据库 | `better-sqlite3`（同步 API，事务方便） | `rusqlite` |
| 后台重活 | `worker_threads` / `utilityProcess` | `std::thread` / `tokio::spawn` |
| 播放内核 | `<video>` + hls.js；P1 加 libmpv 原生插件 | 同左（WebView2 支持 MSE） |

> 选型结论见 `05-技术选型方案.md`。架构本身不依赖选哪个，**这是刻意的**：外壳是可替换件，领域层不是。

## 4. 进程与并发模型

| 执行体 | 承载 | 规则 |
| --- | --- | --- |
| 主进程（单线程事件循环） | 服务编排、IPC、DB 写入、文件操作 | **不许做 >50 ms 的同步计算**；重活必须下沉 |
| 抓取池（worker） | 规则解析、HTML/JSON 抽取、刮削 | 并发上限 10，单请求超时 8 s，单源总超时 15 s |
| 下载池（worker） | 分片下载、校验、合并 | 并发 4 任务 × 4 分片；写盘串行 |
| 图片处理（worker） | 封面裁切/压缩、dataURL 生成 | 只在"上传自定义封面"时用 |
| 播放（渲染进程 + 可选 libmpv 子进程） | 解码与渲染 | 主进程只发指令，不碰帧 |

**为什么 DB 写入放主进程**：只有一个写入者，天然避免 SQLite 的 `SQLITE_BUSY`。读也可以走同一个连接（WAL 下读写不互斥）。

## 5. 模块边界

每个模块只回答三个问题：**我负责什么 / 我不负责什么 / 谁能调我**。

| 模块 | 负责 | 明确不负责 | 上游调用者 |
| --- | --- | --- | --- |
| `source` 源引擎 | 规则 CRUD、校验、并发搜索、健康打分、播放地址解析 | 不做播放、不做下载、不决定 UI 文案 | player / search / download |
| `library` 作品库 | 作品/系列/标签/卷集的读写、进度派生、作品区增删 | 不做抓取（那是 source/scraper）、不做 UI 排序 | 所有视图 |
| `player` 播放 | 选源、代理、会话、进度写回、切源 | 不做解码（交给 `<video>`/mpv） | 播放器视图 |
| `reader` 阅读 | 章节取文/取图、分页、位置记忆、缓存 | 不做漫画图片压缩（交给 download/图片 worker） | 阅读器视图 |
| `download` 下载 | 队列、分段、续传、重试、命名、落盘 | 不管理已下载文件（那是 resource） | 详情页 / 下载中心 |
| `resource` 资源 | 目录树、识别规则、体积统计、删除、盘容量 | 不发起下载 | 资源管理 / 磁盘管理 |
| `scraper` 刮削 | 外部百科抓取、节流、缓存、三态 | 不写作品主表（回填由 library 执行） | 百科页 / 详情页 |
| `search` 搜索 | 本地索引（FTS5）、范围过滤、结果分组 | 不做网络搜索（那是 source） | 顶栏 / 搜索页 |
| `settings` 设置 | 键值、主题、路径、模板 | 不校验业务合法性 | 设置页 / 各模块读 |
| `diag` 诊断 | 日志、崩溃、导出、性能打点 | 不上报（无服务端） | 全局 |

**禁止的调用**：`player` 直接读 DB、`resource` 直接删 `download` 的行、`renderer` 直接拼 SQL 或路径。跨模块一律走对方公开接口。

## 6. 三条关键数据流

### 6.1 搜索 → 详情 → 播放（主闭环）

```
[视图] 输入关键词
   │ invoke search.local(q, scope)
   ▼
[search] FTS5 命中本地库 ──→ 立刻返回（≤150ms，先出结果）
   │
   │ invoke source.search(q, partition)   并发 N 源
   ▼
[source] 每源：规则.search → 抽取 → 归并去重（按 名称+年份+介质）
   │ 单源失败 → 记 SourceError，不影响其它源
   ▼
[视图] 分组渲染；用户点某条 → 入库（library.upsertFromSource）
   │
   ▼
[详情] 点第 N 集 → player.open(workId, ep)
   │
[player] 1) 取该集候选源（本地库 sources 表，按 health 降序）
         2) 逐源 resolve → HEAD 探测 → 拿 m3u8/mp4
         3) 起本地代理 http://127.0.0.1:PORT/p/<token>/index.m3u8
            （注入 Referer/UA，改写分片地址为代理地址）
         4) 渲染进程 hls.js 播放
         5) 每 5s 且 pause/unload 时写回进度
```

**关键点**：代理是**必须**的，不是优化。理由：分片请求同样需要 Referer，且很多源站的 m3u8 里是相对路径 + 自定义 token；把改写集中在一处，播放器就只需要认一个地址。

### 6.2 整季下载

```
[详情] 下载 → download.enqueue(workId, season)
   → 生成任务（每集一个 item，共用一个 parent）
   → 队列排队（并发 4）
   → 每集：解析源 → 拉 m3u8 → 分片并发 4 → .part 落盘 → 校验 → 合并 → 按模板重命名
   → 进度事件节流 500ms 推给视图
   → 完成后通知 resource 增量索引（不重扫全盘）
```

### 6.3 刮削

```
[百科] 重新刮削 → scraper.refresh(workId)
   → 查缓存（7 天）→ 未过期直接用
   → 过期：节流器排队（同域 1 req/s）→ 抓 → 解析 → 写 cache 表 → 回填 library
   → 三态事件：idle / running / done | failed(原因)
```

## 7. 规则引擎：声明式，不是脚本

这是本架构最重要的一条自制约束。

| 方案 | 风险 | 结论 |
| --- | --- | --- |
| 规则里写 JS（`eval` / `new Function` / `vm`） | 远程规则 = 远程代码执行。用户从"链接导入规则"就等于允许任何人往他机器上跑代码 | **禁止** |
| 声明式 JSON（选择器 + 正则 + 路径表达式） | 表达力有限，极端站点写不出来 | **采用**，写不出来的站点单独做适配器 |

- 规则只允许四种原语：CSS 选择器、XPath、JSONPath、正则捕获。
- 不允许循环、不允许条件分支之外的控制流、不允许网络再请求（除规则声明的 `detailUrl`）。
- 详见 `04-接口与源规则规范.md` §4。

**收益**：规则可以安全地备份/导入/分享；解析器可以单测；坏规则只会"这条源不可用"，不会让程序崩。

## 8. 渲染层结构

### 8.1 状态

单一 store（一个可观察对象），**单向数据流**：

```
用户动作 → action → store 变更 → 订阅的视图局部更新
```

- 视图**不许**自己发请求后直接改 DOM 数据；一律走 action。
- 局部更新优先：定稿 §0.9 要求"点追番只换按钮文案"，所以 store 必须支持**按 key 订阅**，否则一次变更全页重渲染，入场动画全重播（红线 82）。
- 路由是 store 的一部分：`route` 变化触发视图切换，`p` / `id` / `q` 等参数即时同步到地址（`04` §2.2）。

### 8.2 视图

- 一个视图 = 一个目录（`views/<name>/index.ts` + `view.css`），只依赖 `shared` 与 store，不 import 别的视图。
- 五个分区的差异**不靠 if 堆**，靠三张表：`partitionFeatures`（功能键）、`partitionSorts`（排序项）、`partitionFilters`（筛选 chips）。新增分区只加表项，见定稿 §0.7。
- 设计令牌只有一个来源（`styles/tokens.css`），组件里出现十六进制色值 = 评审拒绝。

### 8.3 动效

定稿 §4.6 的五条曲线是**路由层的职责**，不是页面各写一份：

- 路由给出 `anim` 类型（`tab/push/pop/part-r/part-l/swap/same`），交给最外层或 `.page-body`；
- 切换同类元素必须 `removeAttribute → offsetWidth → 重挂`（红线 77）；
- 路由签名去重要含全部查询参数（红线 78）。

## 10. 错误与降级

统一错误对象（`04` §6 有完整码表）：

```ts
type AppError = {
  code: ErrorCode;      // E_SOURCE_TIMEOUT / E_RULE_INVALID / E_DISK_FULL …
  message: string;      // 给用户看的一句话（中文，不含堆栈）
  detail?: string;      // 给日志看的技术细节
  retryable: boolean;   // 决定按钮是"重试"还是"换源"
  scope: 'source' | 'item' | 'page';
};
```

**降级矩阵**（与定稿 §0.12「不许静默」对齐）：

| 失败 | 作用域 | 界面表现 | 禁止 |
| --- | --- | --- | --- |
| 单源超时 | source | 结果区少一组，顶部一条"3 个源未响应 · 查看" | 整页转圈 / 静默少数据 |
| 全部源失败 | page | 空态 + "全部源均不可用" + 重试 + 源管理入口 | 显示"没有找到这部作品" |
| 规则非法 | item | 导入时就报字段错，不落库 | 落库后运行时才炸 |
| 分片下载失败 | item | 该集标"失败"，可换源重下 | 整个队列停住 |
| 磁盘写满 | page | 暂停队列 + 明确说哪个盘满了 | 无限重试 |
| 资源目录不可达 | page | 列表标"位置不可用" | 自动删记录 |
| DB 损坏 | app | 启动时提示 + 备份原库 + 新建空库 | 静默清空 |

## 11. 安全边界（五条硬线）

1. **渲染进程零权限**：`nodeIntegration:false`、`contextIsolation:true`、`sandbox:true`；preload 只暴露白名单方法，不暴露 `require`、`fs`、`ipcRenderer` 原体。
2. **不加载远程页面**：源站 HTML 只在主进程里用解析器读成数据。应用内 `webview` 一律不用。
3. **CSP 收紧**：`default-src 'self'`；媒体允许 `http://127.0.0.1:*`（本地代理）与源站域名白名单；禁止 `unsafe-eval`。
4. **路径校验**：所有写操作走 `resolveSafePath(root, userPath)`，拒绝 `..`、拒绝符号链接逃逸、拒绝系统目录。
5. **规则不可执行**：见 §7。

## 12. 可观测性（本地，不上报）

| 项 | 做法 |
| --- | --- |
| 日志 | 按天滚动，保留 7 天，单文件 ≤ 5 MB；`info/warn/error` 三级；每条带 `traceId` |
| 性能打点 | `app.ready` / `home.painted` / `search.done` / `player.firstFrame`，写进日志，设置页可看最近 20 次 |
| 规则命中率 | 每源记录 成功/失败/耗时，源管理页显示（P1） |
| 崩溃 | 捕获未处理异常 → 写 `crash-<ts>.log` → 下次启动提示导出 |
| 诊断包 | 一键导出 zip：日志 + 规则版本 + 库 schema 版本 + 系统信息（**不含**浏览历史与个人路径） |

## 13. 演进与扩展点

| 未来能力 | 预留位置 | 现在要守的约束 |
| --- | --- | --- |
| libmpv / Anime4K | `player/` 下加 `mpv-adapter`，与 `html5-adapter` 同接口 | 播放器视图只认 `PlaybackSession` 接口，不认具体内核 |
| 弹幕 | `player/` 加 `danmaku/`，渲染层 `DanmakuLayer` 组件 | 弹幕数据与视频时间轴解耦 |
| 云同步（P2） | `library/` 的导出接口 | 所有表带 `updated_at`，便于增量 |
| 移动端 | 不可能（本地文件/EXE 依赖） | 不要为"以后上手机"牺牲布局 |
| 多用户 | 不做 | 不要预留 `user_id` 字段，会误导实现 |

## 15. 架构自检（每次改动后过一遍）

1. 这个改动放在 L2 还是 L3？放进 L1 说明分层错了。
2. 新模块有没有写"我不负责什么"？没写就是边界不清。
3. 跨模块调用走的是公开接口，还是直接摸了对方的表/文件？
4. 新增一条失败路径，界面会不会静默？（§0.12）
5. 这次改动让 `shared/` 变了吗？变了有没有通知另一个人？
