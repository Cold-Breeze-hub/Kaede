## 2. 术语

| 术语 | 含义 | 易错点 |
| --- | --- | --- |
| 分区 `partition` | 五种介质之一：`anime / game / manga / novel / music` | 分区 ≠ 分类页。分区是介质，分类页是"这个介质的全部作品" |
| 作品 `work` | 一条可被收藏、有进度的条目 | 音乐的一条作品是**一张碟**，不是一首歌 |
| 系列 `series` | 跨介质的故事归属，如 Fate | 典藏 = 有 `series` 的集合，不是用户手动分组的全部 |
| 源 `source` | 一个资源站，由一条规则描述 | 源是**配置**不是代码，规则坏了不许让程序崩 |
| 规则 `rule` | 声明式 JSON，描述某站如何搜、如何取详情、如何出播放地址 | 见 `04-接口与源规则规范.md` |
| 集数拼图 | 同一作品的多集分散在多个源，按集选源拼成完整一季 | 本软件的核心价值，不是"多源冗余" |
| 进度 `progress` | 由 `read:{at,ch}` 派生出的展示值 | **不许存百分比字符串**，只存读到哪 |
| 介质分化 | 五个分区的功能键、详情主体、阅读/播放形态各不相同 | 不许做"一套控件套五个分区" |

## 4. 角色与场景

单一角色：**本机用户**（软件所有者）。无登录、无权限分级、无多租户。

三个主场景（定稿 §6）：

1. **补老番**：知道名字 → 搜 → 选集 → 播 → 记进度 → 下次从第 N 集续。
2. **跨介质续接**：动画看完 → 详情页"相关作品" → 原作小说 → 阅读器 → 卷/章进度统一。
3. **离线囤片**：详情页发起整季下载 → 下载中心看队列 → 资源管理整理文件夹 → 磁盘管理看占用。

## 6. 非功能需求（NFR）

### 6.1 性能预算

> **F1（2026-10-30 你定的口径）**：下面这些数字**不是硬性指标**，方向是「性能要高、响应要快」，且要**向下兼容——低端机能跑，高端机流畅**（`08` F1 / C3）。
> 因此本表是**设计目标**而非验收条件；S1 阶段在目标机器上实测一次，把实测值回填到「实测基线」列，之后以基线为准。（原「不达标的处理」列保留，作为优化方向。）

| 指标 | 目标 | 实测基线（待填） | 测量方式 | 不达标的处理 |
| --- | --- | --- | --- |
| 冷启动到可交互 | ≤ 2.5 s（SSD，首屏有缓存） | — | 启动打点 `app.ready` | 拆首屏依赖，骨架先出 |
| 首页首屏（Hero + 4 组） | ≤ 800 ms | — | 打点 `home.painted` | 封面懒加载 + 分组延后 |
| 列表滚动 | ≥ 55 fps（58 张封面） | — | DevTools Performance 录制 | 关 backdrop-filter、减阴影 |
| 搜索响应 | ≤ 150 ms（1 万作品） | — | 打点 `search.done` | FTS5 + 前缀索引 |
| 起播时间 | ≤ 3 s（P50） | — | 打点 `player.firstFrame` | 预解析下一集、就近源 |
| 空闲内存 | ≤ 400 MB | — | 任务管理器 | 封面缓存上限 200 张 |
| 安装包 | ≤ 150 MB（含随包的 Chromium） | — | 产物大小 | **v1 不适用**：包体大小你明确不关心（B4），且 v1 不做分发（H5） |

### 6.2 容量

> **F2（2026-10-30）**：没有确定的规模，按「有多少收多少、可控制数量」设计（`08` D2）。下表是**设计容量**（超过就要走索引 / 虚拟滚动），不是预期规模，也不是验收条件。

| 对象 | 设计容量 | 影响 |
| --- | --- | --- |
| 作品 | 10,000 | 搜索与分类页必须走索引 |
| 集/话 | 300,000 | 剧集格必须分页或虚拟滚动 |
| 资源文件 | 200,000 | 资源扫描要能增量 |
| 规则 | 200 | 规则列表要能搜索 |
| 单库体积 | ≤ 500 MB（不含封面与媒体） | 封面存文件系统，不存 BLOB |

### 6.3 可靠性

- **规则坏了不许崩**：任何单源异常被捕获成 `SourceError`，界面显示"这个源暂时不可用"，其它源继续。
- **数据不许半写**：进度、下载、作品区变更一律走事务。
- **杀进程不丢进度**：进度最多丢 5 秒（写入节流窗口）。
- **断盘降级**：资源根目录不可达时，列表显示"位置不可用"，不抛异常、不自动删记录。

### 6.4 可用性与可访问性

- 全部可点元素可 Tab 到达，焦点样式可见（不能用 `outline:none` 而不补替代）。
- 图标按钮必须有 `aria-label`。
- 对比度：正文 ≥ 4.5:1，次要文字 ≥ 3:1。
- 键盘可达的核心路径：搜索 → 结果 → 详情 → 播放 → 退出。

### 6.5 安全与合规

| 项 | 要求 |
| --- | --- |
| 渲染进程权限 | `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`（Electron 45，见 [ADR-001](../adr/ADR-001-shell-electron.md)） |
| 远程内容 | **不加载远程 HTML/JS**。源站返回的 HTML 只在主进程解析成结构化数据，绝不注入渲染进程 |
| 规则 | 声明式 JSON，**禁止 `eval` / `new Function` / 任意脚本** |
| 文件写入 | 只能写用户显式选择的目录 + 应用数据目录；路径必须做 `..` 归一化校验 |
| 外链 | 一律走系统浏览器，应用内不开任意网页 |
| 合规 | 不内置任何资源站地址；规则由用户导入；不公开分发；不做破解/DRM 绕过 |

### 6.6 可维护性

- 模块边界见 `02-系统架构设计.md` §3，跨模块只能走公开接口。
- 新增一个分区/一种列表时，必须先回答"这类东西的状态是什么维度"（定稿 §0.7）。
- 每处"看起来奇怪的兼容代码"必须有注释说明它防的是哪个已知问题。

## 9. 验收标准（v1 的阶段出口）

> **2026-10-30 改**：不再排「从开工到软件成熟」的长表（你在 `08` §3-5 的要求：边用边迭代），只划 v1 内部的阶段，由**出口条件**判断，不由日期判断。阶段定义见 [09 第一版范围](09-第一版范围与迭代计划.md) §4。
> 原 G0–G5 编号**停用**（M0–M5 是周期、G0–G5 是验收，两套编号容易混 —— 这是 `08` §3 列出的第 5 处不清楚）。

| 阶段 | 目标 | 出口条件 |
| --- | --- | --- |
| **S1 骨架与还原** | Electron 壳 + 路由 + SQLite + 全站页面 1:1（走 seed） | 全站页面可点通、无 404 漏网；原型 CSS 在壳里表现一致 |
| **S2 内容与源** | Bangumi 刮削 + 规则导入（含 Kazumi 转换）+ 真实搜索详情 | 能搜到真实作品并显示真元数据；能导入一条社区规则并跑通搜索 |
| **S3 能真的看** | 播放链路 + 跨源拼集 + 失效切换 + miniplayer | **真实源完整播完一集**；杀进程重开回到上次秒数；退出后可小窗 / 纯音频继续 |
| **S4 能囤** | 下载队列 + 断点续传 + 文件夹识别 + 资源管理 | 整季下载完成并验证断点续传；扫描本地目录能识别作品；删除有确认 |
| **S5 v1 收口** | 全站走查 + 自动备份 + 托盘 + 迁移演练 | 定稿 §8 四问全过；红线检查脚本 0 报警；备份与恢复演练通过 |

**一票否决（你在 `08` B4 定的）**：软件框架不能乱；已承诺可用的功能必须真能用。包体大小、界面是否与原像素级一致**都不是**否决项，但界面必须参考定稿且不低于原型（见 `08` §7 C-1）。

每道出口都要过一遍定稿 §8 的四问，结论写进当轮审查清单。**S5 之后进入「用起来 → 补能力 → 再走查」的迭代循环**，不再预先排总工期（`08` F3）。
