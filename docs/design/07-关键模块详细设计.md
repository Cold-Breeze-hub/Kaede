## 1. 播放管线

### 1.1 为什么需要本地代理

不做代理会同时踩三个坑：

| 坑 | 现象 |
| --- | --- |
| 分片请求缺 Referer | 首页 m3u8 拿到了，第 1 个 `.ts` 就 403 |
| m3u8 里是相对路径 + 一次性 token | `<video>` 拼不出正确地址 |
| 跨域 | 渲染进程直接拉源站被 CORS 拒绝 |

代理把这三件事一次性收口：**播放器只认 `http://127.0.0.1:<port>/p/<token>/...`，其它都在主进程里处理。**

```
渲染进程                   主进程代理                        源站
   │ src=…/p/T/index.m3u8     │                                │
   ├─────────────────────────▶│ GET 源 m3u8 (带 Referer/UA)     │
   │                          ├───────────────────────────────▶│
   │      改写后的 m3u8       │◀───────────────────────────────┤
   │◀─────────────────────────┤ 分片地址 → /p/T/seg/0.ts       │
   ├─────────────────────────▶│ 转发分片（透传 Range）           │
```

### 1.2 会话与令牌

```ts
type Session = {
  id: string;            // 随机 16 字节 hex，同时作为 URL 里的 token
  ruleId: string;
  headers: Record<string, string>;   // 从规则与页面继承的 Referer/UA/Cookie
  originBase: string;                 // 源站基地址，用于把相对路径补全
  expiresAt: number;                  // 30 分钟
};
```

- 令牌 = 随机会话 id，**不是**加密后的地址。代理只在自己内存的会话表里查，查不到就 404。
- 端口：启动时选一个空闲端口（`server.listen(0)`），写入会话，不写死。
- 会话过期：30 分钟或播放器关闭。过期后代理返回 410，播放器提示"源已失效，重新解析"。

### 1.3 m3u8 改写规则

```
输入：源站 m3u8（可能多层：master → variant → segments）
处理：
  1. 若含 #EXT-X-STREAM-INF，视为 master：把每个 variant 的 URI 也改写成 /p/T/v/<idx>
  2. 普通分片行：相对路径按 m3u8 自身 URL 解析为绝对，再改写为 /p/T/s/<idx>
  3. #EXT-X-KEY:URI="…" → 改写为 /p/T/k/<idx>（否则解密请求会 403）
  4. #EXT-X-MAP:URI="…" → 同样改写（fMP4 的 init 段）
  5. 其余标签原样透传（含 #EXT-X-BYTERANGE / #EXT-X-DISCONTINUITY）
```

**不做的**：不改分辨率、不重编码、不合并分片（那是下载器的事）。代理只做"地址与请求头"的翻译。

### 1.4 状态机

```
                 open()
                   │
                   ▼
              ┌─────────┐  解析成功   ┌──────────┐  首帧就绪  ┌─────────┐
              │preparing├───────────▶│buffering ├──────────▶│ playing │
              └────┬────┘            └────┬─────┘            └──┬───┬──┘
                   │ 失败                 │ 卡顿>8s               │   │ 暂停
                   ▼                      ▼                       │   ▼
              ┌─────────┐            ┌─────────┐                 │ ┌────────┐
              │  error  │◀───────────┤ stalled │                 │ │ paused │
              └────┬────┘            └─────────┘                 │ └───┬────┘
                   │ 换源成功                                     │     │
                   └──────────────▶ preparing                     │     │
                                                        播完      ▼     │
                                                          ┌─────────┐  │
                                                          │  ended  │◀─┘
                                                          └────┬────┘
                                                               │ 自动连播
                                                               ▼
                                                         下一集 preparing
```

| 状态 | 界面 | 允许的动作 |
| --- | --- | --- |
| `preparing` | 虚化封面 + 作品卡 + "正在寻源与缓冲" | 取消、换源 |
| `buffering` | 同上，进度条转圈 | 暂停、换源 |
| `playing` | 画面 + 两行控件 | 全部 |
| `paused` | 画面定格 | 全部 |
| `stalled` | 画面 + 一行"网络卡住了，正在重试" | 换源、重试 |
| `error` | 虚化封面 + 原因 + 每个源的失败原因列表 | 换源、重试、退出 |
| `ended` | 最后一帧 + "下一集 5 秒后播放" | 取消倒计时、重播 |

**禁止**：`error` 时显示黑屏（定稿 §2.11 要求未播放也不是黑屏）。

### 1.5 选源与回落

```
候选 = ep_sources(ep) ⋈ rules(enabled=1)
排序 = [ok desc, health desc, latency asc, 最近失败冷却]
                 │
   依次尝试（每次 ≤3 s 探测）：
     ├─ 成功 → 记住该 ruleId，写 tick（ok=1, latency）
     └─ 失败 → 写 tick（ok=0, reason），下一个
                 │
   全部失败 → E_ALL_SOURCES_FAILED（附逐源原因）
```

| 细节 | 规定 |
| --- | --- |
| 冷启动 | 首次播放某集时并发探测前 2 个候选（谁先通用谁），减少等待 |
| 播放中失败 | 自动切下一个候选，**保留当前播放位置**，提示"已切换到 X 源" |
| 源过期 | 播放到一半 410/403 → 重新 resolve 同一 ruleId（刷新 token），失败才换源 |
| 冷却 | 连续 3 次失败 → 该源 1 小时内排到队尾（不永久拉黑，源站会恢复） |
| 缓存 | `play_url` 缓存 30 分钟；换集必须重新解析 |

### 1.6 进度写回

```
节流：每 5 s 一次；事件触发立即 flush：pause / seek 结束 / 切集 / 关闭 / 窗口失焦超 30s
单调：同一集内 at 只增不减（用户往回拖不改"看到第几集"，只改秒数）
规则：
  - 动漫：看到 90% 且未 done → 仍不算看完（定稿 §3：只认显式 done）
  - 用户点"标记已看完" → done=1（唯一入口）
  - 切集 → at = 新集数，ch 清空
```

**存哪**：`reading_positions`（`at` = 集数，另有 `kv` 存每集秒数 `pos:<workId>:<ep>`，用于精确续播）。
秒数单独放 `kv`，因为它只服务播放器，不进作品区展示。

## 2. 阅读器

### 2.1 内容模型

```ts
type ReaderBlock =
  | { type: 'text'; text: string }                 // 一个段落
  | { type: 'image'; src: string; w: number; h: number }
  | { type: 'heading'; level: 1 | 2; text: string };
```

- 小说：从源/本地文件取纯文本，按空行切段；标题行识别 `第N章`。
- 漫画：按话取图片列表（懒加载 + 预取后 3 张）。

### 2.2 进度口径（定稿 §2.12 明确）

```
pct = clamp( scrollTop / max(1, scrollHeight - clientHeight) * 100, 1, 100 )
```

- **不是**"第几章 / 总章数"。短章滚不动时 `scrollHeight ≈ clientHeight`，此时 pct 记为 100 只在真正到底时成立（`scrollTop + clientHeight >= scrollHeight - 2`）。
- 写作库：`reading_positions.at = 卷号, ch = 章号`，`ch_of_vol` 用于作品区的卷内百分比；`pct` 是阅读器内部值，退出时可选存 `kv:reader:<workId>:pct` 用于恢复滚动位置。

### 2.3 目录交互

| 动作 | 行为 |
| --- | --- |
| 点卷 | **只展开该卷的话列表**，不跳转、不改当前位置（定稿 §2.12） |
| 点话 | 跳转，`at/ch` 更新，目录收起 |
| 展开另一卷 | 上一卷自动收起（手风琴），避免长列表 |

### 2.4 排版设置

| 项 | 取值 | 落地 |
| --- | --- | --- |
| 字号 | 16 / 18 / 20 / 22 / 24 | `--r-fs` 变量 |
| 行距 | 1.6 / 1.9 / 2.2 | `--r-lh` |
| 字体 | 黑体 / 宋体 | `--r-ff`（系统字体栈，不打包字体） |
| 版心 | 620 / 700 / 820 | `--r-w` |
| 背景 | 跟随主题 / 纸 / 羊皮 / 夜间 | `data-rbg` 属性 + 4 组变量 |

设置写入 `kv`，**切换章节不重置**。

### 2.5 缓存

- 打开一章即写入 `cache/reader/<workId>/<vol>-<ch>.json`（文本）或图片目录。
- 读完下一章后预取再下一章（静默，失败不提示）。
- 缓存上限 200 MB，LRU 淘汰（设置页可清）。

## 3. 下载器

### 3.1 任务模型

```
downloads（一个作品 / 一季 = 一个任务）
  └─ download_items（一集 = 一个条目）
       └─ segments（分片，落在 <target>.part/ 目录，不建表）
```

### 3.2 分片与续传

```
1. 解析 m3u8 → 分片列表（可能是 master，先选最高码率 variant）
2. 计划：每片一个 .part/<idx>.ts；已存在且大小匹配 → 跳过（这就是续传）
3. 并发：4 个分片同时下；每个分片失败重试 3 次（退避 1s/2s/4s）
4. 全部完成 → 按顺序拼接 → 校验（时长或文件头）→ 移动到目标路径
5. 写 item.bytes_done / seg_done，节流 500ms 推事件
```

| 细节 | 规定 |
| --- | --- |
| 并发上限 | 4 个任务 × 4 分片 = 16 连接（可配 2/4/8） |
| 磁盘预检 | 开始前检查可用空间 ≥ 预估大小 × 1.2，不足直接 `E_DISK_FULL` |
| 断盘 | 写入抛 `ENOENT`/`EIO` → 该任务暂停并标"位置不可用"，**不重试**，等用户接回盘 |
| 换源重下 | 保留已下载分片，只重下缺失的；源不同则清空 `.part/` 重来（分片不可混） |
| 命名 | 见 `03` §7 模板；重名自动加 ` (2)` |
| 失败原因 | 只留一行，完整堆栈进日志与 `title` |

### 3.3 状态机

```
queued ──▶ running ──▶ done
  ▲  │        │  ▲
  │  │        │  └── resume ── paused
  │  └── pause┘
  └── retry ── failed
```

- 单个 item 失败不影响同任务其它 item；任务级状态 = 全部 item 的汇总（有失败即 `failed`，但已成功的保留）。
- 「清空已完成」只删 `status=done` 的任务行，**不删文件**（文件归资源管理）。

## 4. 资源扫描与识别

### 4.1 目录约定（识别依据）

```
<root>/<分区文件夹>/<作品文件夹>/<任意层级文件>
        动漫 游戏 漫画 轻小说 音乐
```

识别算法：

```
for dir in root 的一级子目录:
    kind = KIND_BY_DIRNAME[dir.name]        // 「动漫」→ anime
    if !kind: 记入 unrecognized，跳过
    for workDir in dir:
        name = 归一化(workDir.name)          // 去季号、去年份、去方括号组名
        work = 按 (kind, name) 模糊匹配 works   // 完全相等 > 前缀 > 编辑距离≤2
        files = 递归列出（跳过 .part / 隐藏文件）
        写 resource_files(rel_path, kind, work_id?, size, mtime)
```

**未识别出口**：`unrecognized` 列表给两个动作——「指定归属」（选分区 + 关联作品）与「忽略」（置 `ignored=1`，只是隐藏，不动文件）。

### 4.2 增量扫描

| 模式 | 触发 | 行为 |
| --- | --- | --- |
| `full` | 用户点"初始化/重新扫描" | 清空该 root 的 `resource_files` 重建 |
| `incremental` | 下载完成回调、启动时 | 只处理 `mtime > 上次扫描时间` 的目录；不删不存在的记录（避免盘未挂载时误删） |
| 失效检测 | 打开资源管理时 | root 不可达 → 整页标"位置不可用"，**保留记录** |

### 4.3 磁盘容量

- Windows：`GetDiskFreeSpaceExW`（Electron 可用 `fs.statfs`，Node 18.15+ 支持）。
- 分类占用：`SUM(size) GROUP BY kind`，来自 `resource_files`。
- 「其它文件」= 总用量 − 已知分区占用（可能为负，夹到 0）。
- 读不到时：卡片显示"容量不可读"，不拿假数据填（FR-DISK-02）。

## 5. 搜索

### 5.1 两段式

```
输入 → 本地库（FTS5 trigram）→ 立刻出结果
     → 同时并发源站 → 结果到达后"并入"（按名称+年份+介质去重）
```

用户看到的是"先有本地、后有网络"，不是"转圈等 15 秒"。

### 5.2 排序

| 来源 | 排序 |
| --- | --- |
| 本地 | FTS `rank`（bm25）+ 是否在作品区（+0.2）+ 最近访问（+0.1） |
| 源站 | 源 `health` × 名称匹配度（完全相等 1.0 / 前缀 0.8 / 包含 0.6） |
| 混合 | 同一作品合并成一条，标"本地 / 网络 / 两者都有" |

### 5.3 范围

`scope: 'all' | Kind`。只影响查询，**不写 `state.partition`**（定稿 §2.1.1）。

全部范围的结果分组顺序固定：动漫 → 游戏 → 漫画 → 轻小说 → 音乐；此时分区条一个都不高亮。

### 5.4 分词

| 查询 | 策略 |
| --- | --- |
| ≥3 字符 | `works_fts MATCH '"q"'`（trigram 支持中文子串） |
| 1–2 字符 | `name LIKE 'q%'`（走前缀索引） |
| 含空格多词 | 按词 AND，任一命中即可（`OR` 后再按命中词数排） |
| 拼音 | P2，不做 |

## 6. 刮削

### 6.1 Provider 接口

```ts
interface ScrapeProvider {
  id: 'bangumi' | 'moegirl';
  match(work: Work): Promise<{ id: string; score: number } | null>;  // 置信度 <0.7 不采
  fetch(id: string): Promise<WikiContent>;
}
```

### 6.2 节流与缓存

| 项 | 值 | 理由 |
| --- | --- | --- |
| 同域 QPS | 1 | 萌娘/百度对高频访问敏感 |
| 并发 | 1（串行队列） | 刮削不是实时需求 |
| 缓存 TTL | 7 天 | 元数据变化慢 |
| 失败重试 | 2 次，退避 3s/9s | 避免被判定为攻击 |
| 命中率 | 名称归一化后先精确匹配，再取搜索首条（score ≥0.7） | 错配比没有更糟 |

### 6.3 回填策略

- 只填**空字段**（`intro` 为空、`credits` 为空），**不覆盖用户已编辑或已存在的值**。
- 回填前弹一次确认（"将补充 3 项信息"），避免用户发现页面自己变了。
- 三态事件：`idle → running → done | failed`，按钮在 `running` 时禁用（FR-WIKI-02）。

## 7. 音乐播放

### 7.1 队列模型

```ts
type MusicState = {
  workId: string;        // 专辑
  trackIndex: number;    // 第几首（0 基）
  pos: number;           // 秒
  playing: boolean;
  queue: string[];       // 专辑内曲目顺序（也可扩展成多专辑队列）
};
```

- 状态放在 store（渲染层）+ `kv`（持久化当前专辑与曲目），**不放 DB 表**：它不是"进度"，是播放器状态。
- 一首结束 → `trackIndex+1`；最后一首结束 → `playing=false`，**不循环、不跳下一张**（定稿 §2.3.1 ⑤）。
- 迷你播放条贴在底部导航上方（`bottom: var(--bottom-h)`），出现时 `body.mp-on` 顶开 78px，**不许盖住正文最后一行**。

### 7.2 进度条与时间

- 1 秒 tick 推进；拖动时暂停 tick，松手后 seek。
- 时间格式 `m:ss`，总时长来自 `tracks.dur_sec`（下载/流式时以实际为准）。
- 切页面不销毁（状态在 store），关播放条才清。

## 8. 动效落地（定稿 §4.6 的实现细则）

### 8.1 五条曲线的分配

| 动作 | 作用元素 | 曲线 | 时长 |
| --- | --- | --- | --- |
| 切底栏 | `.view` | `tab` | 260ms |
| 换分区 | `.page-body` | `part-r` / `part-l` | 340ms |
| 换主体（作品区切 tab） | `.page-body` | `swap` | 220ms |
| 进子页 | `.view` | `push` | 320ms |
| 退回 | `.view` | `pop` | 300ms |
| 原地重绘 | — | `same`（`animation:none`） | 0 |
| 换一张推荐 | `.hero` | 单独 `heroIn` | 320ms |

### 8.2 三个必踩的坑（都已在定稿里记过，这里给实现）

```ts
// 坑 1：--ease 是「220ms cubic-bezier(...)」，喂给 animation 会被当成 delay
//  → animation 只用纯曲线
.view { animation: viewIn 320ms var(--ease-out); }

// 坑 2：同一元素改 data-anim 的值不会重播
function setAnim(el: HTMLElement, anim: string) {
  el.removeAttribute('data-anim');
  void el.offsetWidth;           // 强制一次布局，重置动画状态
  el.setAttribute('data-anim', anim);
}

// 坑 3：navigate() 同步 route() + 浏览器补发 hashchange，第二次重绘会掐掉动画
function route(next: string, force = false) {
  const sig = signature(next);   // 必须包含 k/c/tag/a 等全部查询参数
  if (!force && sig === state.lastSig) return;
  state.lastSig = sig;
  render();
}
```

### 8.3 作用域检查法

> 问一句：**用户点了什么，屏幕上有几处变？**

- 只有一处变 → 动画只给那一处（`hero`、按钮）；
- 一条控件带（分区条、tab 条）只是换高亮 → **它不参与内容动画**；
- 整页都变 → 才给 `.view`。

`prefers-reduced-motion` 时统一：

```css
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: .001ms !important; transition-duration: .001ms !important; }
}
```

## 9. 性能预算的落地手段

| 预算 | 手段 |
| --- | --- |
| 冷启动 ≤2.5s | 主进程先建窗再建库；DB 只跑迁移检查；首页数据走一次聚合查询 |
| 首屏 ≤800ms | 骨架先出，封面 `loading="lazy"` + 占位色（`accent`）；Hero 图 `fetchpriority=high` |
| 滚动 ≥55fps | 卡片不叠 `backdrop-filter`；阴影用一层；列表用 `content-visibility:auto` |
| 搜索 ≤150ms | FTS5 + 只查必要列；结果集上限 50 |
| 起播 ≤3s | 预解析下一集；候选源并发探测 2 个；代理零拷贝转发 |

**测量方式**：打点写日志（`02` §12），不要靠"感觉快了"。每次性能相关 PR 附一次打点前后对比。

## 10. 模块自检

| 模块 | 自检问题 |
| --- | --- |
| 播放 | 源全挂时界面说的是"源不可用"还是"没找到"？换源后位置保住了吗？ |
| 阅读 | 短章会不会显示 100%？杀进程后回到原处了吗？ |
| 下载 | 拔盘会不会无限重试？失败行高和正常行一致吗？ |
| 资源 | 盘没挂载时会不会把记录删了？忽略是不是真的没删文件？ |

| 音乐 | 最后一首放完会不会偷偷跳下一张？播放条盖住正文了吗？ |
| 动效 | 点一下屏幕有几处动？该动的都动了吗？ |

## 11. v1 增补（2026-10-30 依据 `08` 的答复）

### 11.1 miniplayer 双模式（C4，你新增的需求）

定稿只写了音乐场景的迷你播放条（`#miniplayer`，贴在底部导航上方）。你在 C4 明确：**全站常驻，且动漫播放器退出播放界面后也能选择小窗播放或只播声音，这时的动漫信息也显示在播放条上。**

| 模式 | 触发 | 表现 |
| --- | --- | --- |
| 音乐 | 点「播放全部」或任一曲目 | 连播整张专辑；显示封面 + 曲名 + 进度（定稿已有） |
| **动漫小窗** | **退出播放器页时选「小窗」** | 画面缩到角上（可拖动、2–3 档尺寸），播放条显示**封面 / 作品名 / 第 N 集**；点小窗回全屏播放页 |
| **动漫纯音频** | **退出播放器页时选「只播声音」** | 隐藏画面，只留控制键与作品信息，等同听广播剧 |

约束：

- 播放条**全站常驻**（切页面不中断），高度与底部导航对齐，不许盖住正文（定稿 §2.3 ⑤）。
- 托盘常驻（C1）与 miniplayer 配套：最小化到托盘时继续播。
- 关闭 = 停止播放并写回进度，不是"藏起来继续跑"。
- 小窗不参与定稿 §0.9 的转场动效（它是常驻层，不是页面）。

### 11.2 跨源自动拼集（D3，v1 核心也是最大风险）

你要的是「**跨源自动拼出一整季**，每集可能来自不同站」。这比原设计（按集列候选 + 选最优源）多一层难度。

```
① 并发搜多源 → 得到 N 个候选作品
② 归一到同一季（以 Bangumi 作品 id 为锚，标题/年份/集数辅助）
③ 以 Bangumi 剧集列表为基准集号（真数据，见 08 §6.1）
④ 逐源抓集列表，把每个源的集映射到基准集号（对齐缺集 / SP / OVA / 分季）
⑤ 播放第 K 集 → 在所有拥有 K 的源里按 health 选最优；失败自动回落下一源
```

**风险与建议（见 `09` §5 X-2）**：拼错集比不拼更糟。建议 v1 先落地 ① → ③ → ⑤（**按集选源 + 失败回落**），把「整季自动拼」的 ④ 做成**可开关的增强项**，S3 内验证通过再默认打开。Kazumi 没有跨源拼集，这块没有现成经验可抄，需要我们自己定算法与集数对齐规则。

### 11.3 视频嗅探（X-4，Kazumi 规则导入的配套）

**为什么必须补**：Kazumi 的规则只把程序带到最终播放页，**不给直链**（`08` §6.2）。不补嗅探，导入的社区规则搜得到、播不了。

- **触发时机**：`play.from` / `play.unwrap` 链取不到直链时的兜底，不是主路径。
- **做法**：加载播放页 → 启发式提取
  1. 页面里 `<video src>` / 常见播放器变量约定；
  2. 内联脚本中的 `m3u8` / `mp4` URL（正则 + 长度限制，遵守 `04` §4.1 的反回溯炸弹约束）；
  3. 常见混淆（`atob`、JSON 包裹）复用 DSL 已有的 `unwrap` 链，不新增执行能力。
- **失败语义**：嗅探不到 → 明确报「这个源的播放地址没解析出来」，**不许静默**，也不许假装能播（`01` §6.3 / 定稿 §0.12）。
- **禁止**：为嗅探去执行页面脚本（等于给远程代码开门，违反 ADR-003）。
