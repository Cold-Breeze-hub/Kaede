# 06 · 开发规范（两人协作）

> 版本 v1.0 · 2026-10-30
> 适用：2 名开发，长期维护，Windows 桌面端。
> 这份规范的目的不是"显得正规"，是**让两个人改同一个仓库时不用开会**：谁的目录谁负责，接口谁改谁通知，红线由脚本而不是记忆来守。

---

## 1. 协作模型

### 1.1 分工（方案 C：页面认领 + 能力独占）

> 2026-10-30 定：你在 `08` 的 G1 选了 **C 方案**，且两人都能写全栈 —— 所以不再按「A 只写界面 / B 只写内核」分层。
> 原则：**每个页面有唯一负责人，每个能力域有唯一 owner**，「这个页面谁管」「这个能力谁改」都必须有唯一答案。

| 维度 | 开发 A | 开发 B |
| --- | --- | --- |
| **页面**（唯一负责人，含该页验收） | 首页、分类页、作品区、典藏、系列页、搜索、百科 | 详情页、播放器、阅读器、音乐、我的与设置、下载中心、资源管理、磁盘管理 |
| **能力域**（唯一 owner） | `library`（作品区/典藏/进度）、`search`、`wiki`（Bangumi 刮削） | `source`（规则引擎/导入/嗅探）、`player`（代理/hls/miniplayer）、`download`、`resource`、`disk`、`reader` |
| **外壳** | `shell/` 窗口与托盘；新增 IPC 通道需 B 确认 | — |
| **共用组件** | **A 统一维护**：卡片、进度条、弹层、图标、样式令牌 | **复用，不许复制一份自己改** |
| **共管** | `shared/`（类型与契约）、`core/db/`（schema 与迁移）、`resources/`、文档 | 同左 |

**判断标准（替代原分层标准）**：

1. 页面负责人可以端到端改这个页面（含它依赖的能力域），**但不得改对方独占的能力域** —— 需要改动就在 `shared/` 提契约变更，由 owner 实现。
2. 两人都能写全栈，因此**不禁止** A 写 SQL 或 B 写 tsx；禁止的是**同一个能力域出现两个 owner**。
3. 共用组件只有一份，出现在两个地方就是 bug。

**分组原则（G2：时间可能不对等）**：上面两组按「可独立交付」切，不按工作量对半切 —— 任一人被占用时，另一人仍能把自己的一组页面独自推到可运行状态。A 组靠 Bangumi 刮削即可独立成形；B 组靠规则引擎 + 播放器独立成形，两边只在「打开详情 / 起播 / 下载」三个契约点上交汇。

### 1.2 契约先行

```
① 一起改 shared/        →  ② 合并（一天内）
③ A 按类型写视图，B 按类型写实现（并行）  →  ④ 联调只对契约，不对人
```

- **先合并契约，再写实现**。反过来的结果一定是"字段名一个 `cover` 一个 `coverPath`"。
- 契约阶段 Any 可以使用 `unknown` + TODO 注释，但**实现阶段不许留 TODO**。

### 1.3 同步节奏

| 频率 | 形式 | 内容 |
| --- | --- | --- |
| 每天 10 分钟 | 文字同步 | 昨天做了什么、今天动哪些文件、有没有要改契约 |
| 每周 30 分钟 | 走查 | 拿定稿 §8 四问过一遍本周新增界面 |
| 每里程碑 | 复盘 | 哪些红线又踩了、要不要加检查脚本 |

## 2. 仓库与所有权

```
kaede/
├─ shared/              ★ 共管（契约，改动需双方同意）
├─ src/
│  ├─ pages/discover/   A 独占（首页 · 分类页 · 作品区 · 典藏 · 系列页 · 搜索 · 百科）
│  ├─ pages/consume/    B 独占（详情 · 播放器 · 阅读器 · 音乐 · 我的 · 下载 · 资源 · 磁盘）
│  ├─ components/       A 独占（共用组件；B 复用，不许复制）
│  └─ shell/            A 独占（窗口与托盘；新增 IPC 通道要 B 确认）
├─ core/
│  ├─ library/          A 独占
│  ├─ search/           A 独占
│  ├─ wiki/             A 独占（Bangumi 刮削）
│  ├─ source/           B 独占（规则引擎 · 导入 · 视频嗅探）
│  ├─ player/           B 独占（本地代理 · hls · miniplayer）
│  ├─ download/         B 独占
│  ├─ resource/         B 独占
│  ├─ disk/             B 独占
│  ├─ reader/           B 独占
│  └─ db/               ★ 共管（schema 与迁移，改表必须两人确认）
├─ resources/           ★ 共管
├─ tests/               A 管 e2e/，B 管 unit/ 与 fixtures/
└─ docs/                ★ 共管
```

规则：

1. **独占目录**：另一个人可以读、可以提 issue，但不直接改。
2. **`shared/` 改动**：PR 标题加 `[contract]`，必须 @ 对方，24 小时内响应。
3. **`core/db/` 改动**（schema / 迁移）：同样走 `[contract]`，且必须附迁移演练结果（`03` §迁移）。
4. **跨组改动**：一个 PR 里同时动了 A 组和 B 组的目录 → 拆成两个 PR（联调除外，需在描述里说明）。
5. **新增顶层目录**：先讨论。目录一旦建了就会长出东西。

## 3. 分支与提交

### 3.1 分支

| 项 | 规则 |
| --- | --- |
| 主干 | `main`，**任何时刻可构建、可运行** |
| 工作分支 | `feat/<scope>-<slug>`、`fix/<scope>-<slug>`、`chore/<slug>` |
| 寿命 | ≤ 3 天。超过就拆小，或先合一个"能跑但不完整"的版本到 `main` |
| 同步 | 合并前 `git rebase main`，保持线性 |
| 合并方式 | **squash merge**，一个功能一个提交 |

> 两人项目不需要 `develop`。多一条长期分支就多一次合并地狱。

### 3.2 提交信息（Conventional Commits）

```
<type>(<scope>): <主题，中文，不超过 50 字>

[可选正文：为什么这么改，不写"改了什么"——diff 已经写了]
```

| type | 用途 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 修缺陷 |
| `refactor` | 不改行为的重构 |
| `perf` | 性能 |
| `style` | 纯样式（含 CSS 调整） |
| `docs` | 文档 |
| `test` | 测试 |
| `chore` | 构建/依赖/脚本 |

`scope` 取值：`view` `core` `db` `source` `player` `reader` `dl` `res` `wiki` `shell` `shared` `style` `build` `docs`。

示例：

```
feat(player): 选集面板从下往上弹出，当前集高亮
fix(shelf): 管理态不再另起一行，grid.top 前后相等
refactor(core): 选源打分抽成纯函数，便于单测
[contract] feat(shared): source.resolve 返回 candidates 列表
```

### 3.3 PR

- 标题同提交规范；描述里必须有：**改了什么 / 为什么 / 怎么验**。
- 改动行数 **≤ 400**（不含 lock 文件与生成物）。超了拆。
- 附截图或录屏（界面改动必须；动效改动给 gif）。
- 自测清单勾完再请评审：

```markdown
- [ ] 本地跑过 `npm run verify`（typecheck + lint + test）
- [ ] 界面改动：390 / 1000 两个宽度都看过
- [ ] 有动效改动：确认没有整页重渲染（红线 82）
- [ ] 涉及定稿条目：写明章节号
- [ ] 新增封面容器：已写 `position:relative; overflow:hidden`（§0.13）
```

## 4. 代码规范

### 4.1 TypeScript

| 规则 | 说明 |
| --- | --- |
| `strict: true`，`noUncheckedIndexedAccess: true` | 从第一天开，后期再开等于重写 |
| **禁止 `any`** | 用 `unknown` + 类型守卫；实在要逃，写 `// eslint-disable-next-line` 并注明原因 |
| **禁止 `as` 断言跨层** | 尤其 `as Work`：数据从库里出来必须先过校验函数 |
| 类型定义只在 `shared/` 与模块内 | 视图里不许重新定义 `Work` |
| 导出显式 | 不许 `export *`（会导致循环依赖难查） |
| 时间 | 一律 `number`（ms）；不传 `Date` 跨进程 |
| 空值 | 用 `null` 表示"没有"，不用 `undefined` 混用 |

### 4.2 命名

| 对象 | 规则 | 例 |
| --- | --- | --- |
| 文件（组件） | `PascalCase.tsx` | `CoverBox.tsx` |
| 文件（逻辑） | `kebab-case.ts` | `resolve-source.ts` |
| 变量/函数 | `camelCase` | `deriveProgress` |
| 常量表 | `SCREAMING_SNAKE` | `PARTITION_FEATURES` |
| CSS 类 | `kebab-case`，BEM 变体用 `__` `--` | `.shelf-card__meta--dim` |
| CSS 变量 | `--s-4` `--t-md` `--r-md`（沿用定稿） | 不新造前缀 |
| IPC 通道 | `domain.verb` | `library.shelf.add` |
| 错误码 | `E_XXX_YYY` | `E_RULE_NO_MATCH` |
| 数据库 | 表 `snake_case` 复数，字段 `snake_case` | `ep_sources` |

### 4.3 函数与模块

- **单一职责**：一个函数只做一件事，超过 40 行先想能不能拆。
- **纯函数优先**：派生计算（`deriveProgress` / `fmtCount` / `albumDur` / 选源打分）必须是纯函数，输入输出可单测。
- **不许在视图里算业务**：`pct` 的计算只能在 `core/`，视图只拿结果。
- **副作用集中**：fs / http / db 只出现在 `core/`，且每个模块一个入口文件。

### 4.4 错误处理

```ts
// ✅ 预期内的失败：返回 Result，不抛
const r = await engine.resolve(ep);
if (!r.ok) return showSourceError(r.error);

// ✅ 真正意外：抛，但在边界捕获成 AppError
try { ... } catch (e) { throw toAppError(e, 'E_INTERNAL'); }

// ❌ 绝对禁止
try { ... } catch {}
catch (e) { console.log(e) }
```

- **禁止空 catch**。抓了就要么处理、要么上报、要么转成用户能懂的话。
- 面向用户的 `message` 不许出现英文错误码、堆栈、`undefined`。
- 不许 `alert()`；一律用应用内对话框组件。

### 4.5 注释

只在三种情况写：

1. **为什么这么写**（尤其是"看起来多余"的代码）：

   ```ts
   // 同一个元素上换 data-anim 的值不会重播动画，必须摘掉属性再挂回去（定稿红线 77）
   el.removeAttribute('data-anim');
   void el.offsetWidth;
   el.setAttribute('data-anim', anim);
   ```

2. **防的是什么已知 bug**：写清症状与复现路径。
3. **对外契约**：接口一句话说明"保证什么 / 不保证什么"。

禁止：`// 设置标题`、`// 循环数组`、用注释代替删掉的代码（交给 git）。

### 4.6 CSS

| 规则 | 依据 |
| --- | --- |
| **颜色只能来自令牌**（`var(--c-*)`），`tokens.css` 之外不许出现十六进制 | 定稿 §4.1；主题切换靠它 |
| 间距只用 `--s-1..--s-8`，字号只用 `--t-xs..--t-3xl` | 定稿 §4.4 |
| **装封面的容器必须 `position:relative; overflow:hidden`** | §0.13，已经复发三次 |
| 滚动容器不许常驻 `will-change` | §0.14 |
| 六列网格必须 `repeat(6, minmax(0,1fr))`，卡片补 `min-width:0` | 红线 55 |
| 图标与文字对齐靠 `display:flex; align-items:center`，不靠 `line-height` 猜 | §2.1 |
| 不许 `!important`（除非覆盖第三方，需注释） | — |
| 一个视图一个 CSS 文件，类名加视图前缀（`.shelf-*`） | 避免全局撞名 |

### 4.7 视图层专用规则

- **局部更新优先**：点按钮只改按钮，不重渲染容器（§0.9）。
- **不许手写 `innerHTML`**：用 DOM API 或框架渲染；确需拼接，必须先过 `escapeHtml`。
- **可点元素必须是 `button` 或带 `role`+`tabindex`**，键盘可触发。
- **图片必须有 `alt`**（装饰性图 `alt=""`）。
- 动画只给"真的变了的那一块"（§0.9 作用域表）。

## 5. 把红线变成可执行检查

定稿有 120 条红线 + 14 条铁律。**靠记忆守不住**，把它们分给工具：

| 红线类别 | 检查方式 | 落点 |
| --- | --- | --- |
| 硬编码色值 | stylelint `declaration-property-value-disallowed-list` + 自定义脚本 | `npm run check:redline` |
| 封面容器漏 `position:relative` | 脚本扫 CSS：类名含 `-cover`/`cover-` 的规则块必须有该属性 | 同上 |
| 滚动容器常驻 `will-change` | 脚本扫 `.view` 选择器块 | 同上 |
| `eval` / `new Function` | ESLint `no-eval` `no-new-func` + 脚本扫 `core/` | lint |
| 直接 `innerHTML` | ESLint `no-restricted-properties` | lint |
| 残留 `console.log` | ESLint `no-console`（允许 `warn/error`） | lint |
| 未使用变量 / 导入 | `tsc --noEmit` + ESLint | verify |
| 空 catch | ESLint `no-empty`（`allowEmptyCatch:false`） | lint |
| 页面出现"设计文档"字样 | 脚本扫 `src/**` 关键词（红线 113） | check:redline |
| 文案里出现"（演示）"以外解释性文案 | 人工评审（机器判不了语义） | 评审清单 |

`scripts/check-redline.mjs` 建议输出：

```
✗ src/views/detail/view.css:142  封面容器 .det-cover 缺少 position:relative  (§0.13)
✗ src/views/home/view.css:88     出现硬编码色值 #F7F4EC，请改用 var(--c-bg)  (§4.1)
✓ 其余 8 项通过
```

把它挂进 `npm run verify`，PR 模板里勾"已跑 verify"。

## 6. 评审规范

### 6.1 评审什么

对每个 PR，评审者按顺序问五句：

1. **它做的是定稿里的事吗？** 章节号对不对，有没有自作主张加功能。
2. **有没有第二条入口？**（§0.3 不做重复功能）
3. **失败时会怎样？** 断网、源挂、盘满、规则坏——四种情况走一遍。
4. **两个人明天还能改吗？** 命名、边界、有没有把逻辑塞进视图。
5. **删掉这段代码，用户会少什么？** 答不出就是无效信息（§0.2）。

### 6.2 界面 PR 额外过定稿 §8 四问

> 这页干什么 / 这块信息需要吗 / 别处有没有 / 这页能不能做完

结论写进 PR 评论，一句话一条。

### 6.3 拒绝要带方向

```
❌ "这个写法不太好"
✅ "选源逻辑写在视图里了（src/views/detail/index.tsx:88），
   应该走 core/player/resolveSource；否则单测覆盖不到，
   而且下次换播放内核要改视图。建议把 88–140 行搬到 core/player/resolver.ts。"
```

### 6.4 评审时效

- 普通 PR：**24 小时内**给结论（通过 / 要改 / 需要讨论）。
- `[contract]` PR：**当天**。
- 卡住超过一天 → 直接语音/当面说，不要堆评论。

## 7. 测试规范

### 7.1 分层

| 层 | 工具 | 覆盖对象 | 目标 |
| --- | --- | --- | --- |
| 单元 | Vitest | `shared/` 纯函数、派生计算、选源打分、命名模板、规则解析 | **`core/` 行覆盖 ≥ 70%**，纯函数 ≥ 90% |
| 契约 | Vitest 快照 | IPC 通道与类型 | 变更必须显式出现在 diff 里 |
| 组件 | Vitest + DOM | 卡片、工具条、对话框、chips | 关键交互（选中、禁用、确认） |
| E2E | Playwright（`_electron`） | 五条主闭环 | 全绿才算可发布 |
| 手工 | 定稿 §8 四问 | 全站走查 | 每里程碑一次 |

### 7.2 必须有的五条 E2E

1. **返回先回来处**：作品区 → 点封面 → 播放器 → 关闭 → 详情 → 返回 → 回到作品区。
2. **换一个不重播**：首页点"换一个"，功能区与题材分组的入场动画不重播（用 `animationstart` 计数）。
3. **管理态零位移**：进出管理，`.shelf-grid` 的 `top` 完全相等。
4. **搜索范围**：全部范围搜"Fate"出 5 个分区，分区条一个都不高亮；切单分区后高亮。
5. **404**：`#/detail/nope` 显示 404 与出口按钮，不回落到首页。

### 7.3 规则引擎的测法

源站会变，不能拿真实站点做 CI。

| 做法 | 说明 |
| --- | --- |
| **录制样本** | 每个内置规则存 3 份真实响应到 `tests/fixtures/<ruleId>/`（搜索页、详情页、播放页） |
| **回放** | 测试时用 mock HTTP 返回样本，断言抽取结果与快照一致 |
| **规则语法测试** | 每个变换（`url/regex/json/atob/slice`）各 3 个用例（正常/空/畸形） |
| **失败语义** | 断言"列表为空"返回 `E_SOURCE_EMPTY`，而"选择器不命中"返回 `E_RULE_NO_MATCH` |

### 7.4 测试禁忌

- 不许为了过测试改断言（先确认代码错还是测试错）。
- 不许在测试里 sleep 等异步，用 `waitFor`。
- 不许提交 `.only`。

## 8. 文档规范

| 文档 | 何时写 | 写多长 |
| --- | --- | --- |
| **ADR**（`docs/adr/NNN-*.md`） | 做了不可逆或会被问"为什么不用 X"的决定 | 半页：背景/选项/决定/后果 |
| **CHANGELOG.md** | 每个里程碑 | 按 `新增/修改/修复/移除` 四类，只写用户能感知的 |
| 代码注释 | 见 §4.5 | 只写"为什么" |
| 设计定稿 | 界面有任何变化 | **先改原型，再改定稿，再改代码**（顺序不许乱） |

定稿与代码冲突时：**定稿优先**，代码按定稿改；如果定稿本身不合理，先改定稿（并记录原因），再改代码。不许"代码先跑起来再说"。

## 9. 完成定义（DoD）

一个任务只有全部满足才算完成：

```
□ 功能按定稿实现，章节号写进 PR
□ verify 全绿（typecheck + lint + test + check:redline）
□ 新增逻辑有单测；新增界面有 E2E 或截图
□ 失败路径走过（断网/源挂/盘满/空数据）
□ 390 与 1000 两个宽度都看过
□ 键盘可达、焦点可见
□ 没有 console.log、没有 TODO、没有注释掉的代码
□ 契约变了 → 对方已确认
□ 文档/CHANGELOG 需要更新的已更新
```

## 10. 版本与发布

| 项 | 规则 |

## 11. 冲突预防

两人项目最大的隐性成本是"改同一个文件"。

| 措施 | 做法 |
| --- | --- |
| 目录隔离 | §2，最重要的一条 |
| 契约单点 | 所有跨层类型只在 `shared/`，两边都 import |
| 共享文件清单 | `package.json` / `tsconfig` / `vite.config` / `shared/**` / `docs/**` —— 改之前先说一声 |
| 大改动预告 | 要重构某模块，提前一天在同步里说，别在 PR 里给惊喜 |
| 格式化统一 | Prettier + 保存时格式化，杜绝"只改了空格"的冲突 |
| 锁文件 | 只有 A 执行依赖升级（`npm install` 后立即提交 lock），避免两人同时改 |

---

## 12. 十条硬禁

1. 在视图层写 SQL、读文件、发 HTTP。
2. 在 `core/` 里 import 任何 `src/` 的东西。
3. 用 `any` 或 `as` 把外部数据直接当领域类型。
4. 空 `catch`，或 catch 后只 `console.log`。
5. 硬编码颜色/间距/字号，绕过令牌。
6. 新增封面容器不写 `position:relative; overflow:hidden`。
7. 为了让页面"看起来对"而加解释性文案（§0.4）。
8. 静默失败：出错不提示、回落首页、空壳页。
9. 同一个能力做第二个入口。
10. 先合并实现，再补契约。

> 违反第 6、8、9 条时不用讨论，直接返工——这三条是复发率最高的。
