## 1. 契约总览

```
┌────────────┐  IPC（本文 §2）   ┌──────────────┐
│  视图层     │ ───────────────▶ │  应用服务     │  领域接口（§3）
│  renderer  │ ◀─────────────── │  core        │ ──────────────▶ 基础设施
└────────────┘   事件（§7）      └──────────────┘
                                       │
                                       ▼ 规则解释（§4）
                                  ┌──────────┐
                                  │ 源站 HTML │
                                  └──────────┘
```

三条铁律：

1. **通道白名单**：preload 只暴露下表列出的方法，不暴露 `ipcRenderer` 本体。
2. **参数与返回值必须可序列化**（JSON）。不许传 `Date`、`Buffer`、函数、类实例。时间一律 `number`（ms）。
3. **返回值统一信封**：`{ ok: true, data }` 或 `{ ok: false, error: AppError }`。**不抛异常跨进程**。

```ts
// shared/ipc-contract.ts
export type Result<T> = { ok: true; data: T } | { ok: false; error: AppError };
```

### 3.2 播放会话

```ts
export interface PlaybackSession {
  id: string;
  workId: string;
  ep: number;
  /** 本地代理地址，渲染层只认这个 */
  url: string;                       // http://127.0.0.1:53820/p/<token>/index.m3u8
  kind: 'hls' | 'mp4';
  ruleId: string;
  ruleName: string;                  // 播放器"源"面板显示
  candidates: { ruleId: string; name: string; quality?: string; ok: boolean }[];
  startAt: number;                   // 续播秒数，0 = 从头
  subtitles: { lang: string; url: string }[];
  audioTracks: { lang: string; index: number }[];
}
```

### 3.3 选源算法（`resolve` 的实现约定）

```
candidates = ep_sources (该集) ⋈ rules(enabled=1)  按 [ok desc, health desc, latency asc]
for c in candidates:
    url = c.play_url ?? 解析(c.page_url)
    探测：HEAD 或 前 2 个分片 GET，超时 3s
    成功 → 记 ok=1, latency，返回
    失败 → 记 ok=0，reason，继续下一个
全部失败 → throw E_ALL_SOURCES_FAILED（带每个源的失败原因）
```

- 缓存 `play_url` 有效期 **30 分钟**（源站 token 会过期）。
- 失败不永久拉黑，只降 `health`；连续 3 次失败该源在 1 小时内排到队尾。

## 4. 源规则 DSL v1

### 4.1 设计取舍

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 形态 | **声明式 JSON** | 规则可导入/分享/单测；远程规则不能变成远程代码执行 |
| 表达力 | 选择器 + 变换链 | 覆盖 90% 站点；剩下的做内置适配器 |
| 版本 | `specVersion: 1` | 解析器按版本分支，老规则永远能跑 |
| 失败 | 逐字段报错 | 导入时就知道哪一行错，不留到运行时 |

**明确禁止**：`eval`、`new Function`、`vm`、`Function` 构造、正则里的回溯炸弹（解析器限制 pattern 长度 ≤ 500，禁止嵌套量词）。

### 4.2 结构

```json
{
  "specVersion": 1,
  "id": "demo-anime",
  "name": "示例站",
  "version": "1.0.0",
  "partition": "anime",
  "baseUrl": "https://demo.example",
  "encoding": "utf-8",
  "headers": {
    "User-Agent": "Mozilla/5.0 …",
    "Referer": "https://demo.example/"
  },
  "rateLimit": { "qps": 1, "concurrency": 2, "timeoutMs": 8000 },

  "search": {
    "url": "/search?q={keyword}&page=1",
    "list": "css:.search-item",
    "fields": {
      "name":      "css:.title@text | trim",
      "detailUrl": "css:a@href | url",
      "cover":     "css:img@data-src | url",
      "year":      "css:.year@text | regex:(\\d{4}) | number"
    }
  },

  "detail": {
    "fields": {
      "intro": "css:.summary@text | trim",
      "tags":  "css:.tags span@text[]"
    },
    "episodes": {
      "list": "css:.ep-list a",
      "n":    "css:@text | regex:(\\d+) | number",
      "url":  "css:@href | url"
    },
    "volumes": {
      "list": "css:.vol-list li",
      "n":    "css:.vol-no@text | regex:(\\d+) | number",
      "name": "css:.vol-name@text",
      "chapters": {
        "list": "css:.ch-list a",
        "n":    "css:@data-ch | number",
        "title":"css:@text"
      }
    }
  },

  "play": {
    "kind": "m3u8",
    "from": "css:video@src",
    "headers": { "Referer": "{detailUrl}" },
    "unwrap": ["atob", "json:data.url"]
  }
}
```

### 4.3 表达式语法

```
expr      := selector ( '@' attr )? ( '|' transform )*
selector  := 'css:' <css选择器>
           | 'xpath:' <xpath>
           | 'json:' <jsonpath>          // 响应是 JSON 时
           | 'raw:'
attr      := 'text' | 'html' | 'src' | 'href' | 'data-src' | <任意属性名>
suffix    := '[]'                       // 取数组
transform := trim | url | number | int | date:<fmt> | atob
           | regex:<pattern>(:<group>)? | json:<path>
           | join:<sep> | default:<literal> | slice:<start>:<end>
```

语义：

| 变换 | 行为 | 例 |
| --- | --- | --- |
| `url` | 相对地址按 `baseUrl`（或当前页面）解析为绝对地址 | `/v/123` → `https://demo.example/v/123` |
| `regex` | 取第一个捕获组；无匹配则整个字段失败 | `第 5 集` → `5` |
| `number` / `int` | 去非数字后转数值；无法解析 → 字段失败 | `1.4 万` → 14000（需先 regex） |
| `json` | 对 JSON 字符串取路径 | `{"d":{"u":"x"}}` → `x` |
| `atob` | Base64 解码（常见于播放地址混淆） | |
| `default` | 前面为空时的兜底值 | |
| `slice` | 数组切片 | `slice:0:6` |

**空值规则**：`text` 与 `@指定属性` 取不到时返回 `null`，不返回空字符串（区分"没有这个字段"与"字段是空的"）。

### 4.4 必填与约束

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `specVersion` | ✓ | 必须为解析器支持的版本 |
| `id` | ✓ | `[a-z0-9-_]{2,40}`，全局唯一，冲突则拒绝导入 |
| `name` | ✓ | ≤ 24 字 |
| `baseUrl` | ✓ | 必须 https（http 需用户显式确认） |
| `search.url` | ✓ | 必须含 `{keyword}` |
| `search.list` + `fields.name` + `fields.detailUrl` | ✓ | 缺一不可搜 |
| `detail.episodes` 或 `detail.volumes` | 二者其一 | 都没有则该规则只能搜不能播，导入时警告 |
| `play.kind` | 有 `play` 时必填 | `m3u8 / mp4 / iframe / json` |
| `rateLimit.qps` | — | 默认 1，上限 5（防止被用户手改成封 IP） |

### 4.5 规则版本与兼容

| 变化 | 处理 |
| --- | --- |
| 加可选字段 | specVersion 不变 |
| 改语义 / 删字段 | specVersion +1，解析器保留 v1 分支 |
| 某站改版 | 只改该规则 `version`，不动 specVersion |
| 内置规则更新 | 随应用更新；用户改过的规则**不覆盖**（`origin=imported` 跳过） |

## 5. 解析管线的失败语义

**核心原则：把"没搜到"和"源坏了"分开。** 混在一起，用户会以为这部作品不存在（定稿 §0.12）。

| 阶段 | 失败情形 | 错误码 | 可重试 | 界面表现 |
| --- | --- | --- | --- | --- |
| 请求 | DNS/连接失败 | `E_SOURCE_UNREACHABLE` | ✓ | 该源不出结果，计入"未响应" |
| 请求 | 超时（8 s） | `E_SOURCE_TIMEOUT` | ✓ | 同上 |
| 请求 | 403 / 429 / 验证码页 | `E_SOURCE_BLOCKED` | ✗ | "该源要求验证，已跳过" |
| 抽取 | 列表选择器 0 命中 | `E_RULE_NO_MATCH` | ✗ | "规则可能已失效（列表为空）"，指向源管理 |
| 抽取 | 列表有命中但 `name` 全空 | `E_RULE_NO_MATCH` | ✗ | 同上，提示具体字段 |
| 抽取 | 命中 0 条且页面正常 | `E_SOURCE_EMPTY` | ✗ | **"没有找到"**（这是真没有） |
| 详情 | 详情页 404 | `E_WORK_NOT_FOUND` | ✗ | 该条结果标灰 |
| 播放 | 无 `ep_sources` | `E_NO_SOURCE` | ✗ | 播放器："这一集没有可用源" |
| 播放 | 全部候选失败 | `E_ALL_SOURCES_FAILED` | ✓ | 列出每个源的原因 + "换源重试" |
| 播放 | 解析出 DRM / Widevine | `E_DRM_UNSUPPORTED` | ✗ | "该源使用加密流，不支持" |
| 规则 | 校验不通过 | `E_RULE_INVALID` | ✗ | 导入时逐字段报错 |

## 7. 事件契约

单向推送，渲染层订阅后自动解绑（`Unsubscribe`）。

| 事件 | 载荷 | 节流 |
| --- | --- | --- |
| `download.progress` | `{ id, itemId, n, doneBytes, totalBytes, speedBps, status }` | 500 ms |
| `download.done` | `{ id, ok, failedItems }` | — |
| `player.state` | `{ sessionId, state: 'loading'\|'playing'\|'paused'\|'ended'\|'error', pos?, err? }` | 200 ms |
| `source.health` | `{ ruleId, health, lastErr }` | 5 s |
| `scraper.state` | `{ workId, state: 'idle'\|'running'\|'done'\|'failed', err? }` | — |
| `settings.changed` | `{ key, value }` | — |
| `resource.scanned` | `{ rootId, scanned }` | — |

**约定**：事件只做"通知变了"，不携带完整列表。要完整数据请调对应 `get/list`（避免两套真相）。

## 8. 健康度与选源打分

```
单次结果：ok = 1 | 0
health = 0.7 * EMA(ok, α=0.2) + 0.3 * (1 - clamp(latency/8000, 0, 1))
```

| 场景 | 排序 |
| --- | --- |
| 搜索 | 结果按 `health * 相关度` 排，但不跨源去重前不排序 |
| 选源 | `ok desc, health desc, latency asc` |
| 源管理列表 | `health desc`，低于 0.4 标"可能失效" |

`health` 只驱动排序与提示，**不在任何界面显示具体数值**（避免用户误以为这是"评分"）。

## 9. 兼容 Kazumi 规则（**v1 / S2**）

> **2026-10-30 提前**：原标 P1。你在 `08` A4 明确要「可以从 Kazumi 社区规则直接导入」，因此提前到 v1 的 S2 阶段。调研依据见 `08` §6.2。

### 9.1 Kazumi 规则长什么样

一份 JSON「网站说明书」（仓库示例形态）：

```json
{
  "api": "1", "type": "anime", "name": "AGE", "version": "1.5",
  "baseURL": "https://example.com/",
  "searchURL": "https://example.com/search?query=@keyword",
  "searchList": "//div/div/section/div/div/div/div",
  "searchName": "//div/div/h5/a",
  "searchResult": "//div/div/h5/a",
  "chapterRoads": "//div/div/section/div/div/div/div/div",
  "chapterResult": "//ul/li/a"
}
```

要点：

- 规则只负责两件事：**搜索**（作品名 + 来源标识/地址）和**选集**（播放线路 + 剧集）。
- `api` 指示解析类型：XPath 或 API（受限 JSONPath）；搜索与选集可分别选（纯 XPath / 纯 API / API 搜索 + XPath 选集）。
- **视频直链的启发式嗅探是 Kazumi 内部实现**，规则只把程序带到最终播放页。
- 分发：社区仓库（约 86 份规则）、`kazumi://` 链接、剪贴板、本地 `.json`。**Kazumi 本体不内置任何番剧源与默认规则**——引擎开源、规则社区共笔、内容归内容站。

### 9.2 字段映射（`kazumi2v1.ts`）

只做字段映射，**不做语义推断**；无法映射的字段进 `unsupported`，导入时提示。**不做运行时双解析**——两套解析器的维护成本会吃掉收益。

| Kazumi 字段 | DSL v1 对应 | 转换 |
| --- | --- | --- |
| `baseURL` | `baseUrl` | 直接 |
| `searchURL` | `search.url` | `@keyword` → `{keyword}` |
| `searchList` | `search.list` | XPath → 加 `xpath:` 前缀 |

### 9.3 两个必须一并做的事

1. **能力分级**：Kazumi 规则只有「搜索 + 选集」，缺详情、元数据、音乐曲目、漫画话、小说章、游戏下载。导入后标 `tier: 'basic'`，缺失字段走 **Bangumi 刮削补齐**（`08` §6.1）。
2. **必须补视频嗅探**：这类规则只把程序带到播放页，没有直链 —— 不补嗅探，导入了也播不了。见 `07` §11.3。

## 10. 契约变更流程

1. 改 `shared/ipc-contract.ts` → 写清为什么改；
2. 跑 `npm run test:contract`（快照测试会 diff 出新增/删除的通道与字段）；
3. PR 里 @ 另一个人；
4. 合并后另一侧按新类型对齐，**不许一边合并一边留 TODO**。

> 契约快照是防"两个人各写一套字段名"的唯一有效手段。字段名 `coverPath` 还是 `cover_path` 这种分歧，靠口头约定一定失败。
