# 05 · 技术选型方案

> 版本 v1.0 · 2026-10-30
> 本文的作用：**把可选路线摆清楚、给出推荐并留档理由**。D1–D4 已于 2026-10-30 拍板（见 §8 与 `docs/adr/`）；**D5 分发延后到 v1 之后**（你确认 `08` H5「暂不考虑分发，第一版出来后再说」）。

| **D3 播放内核** | **`<video>` + hls.js** ✅，P1 挂 libmpv | libmpv 优先 | 先快后精；Anime4K/多音轨要等 P1 |

## 1. 选型方法

```
定稿 → 抽出硬约束 → 逐条给权重 → 候选方案打分 → 看不可逆的部分 → 拍板
```

只做一件事：**判断"这个方案能不能把原型变成产品，且不重写原型"**。
"团队想学新技术""社区热度高"都不进权重表——两人项目里，学习成本就是工期。

## 3. 候选方案

### A. Electron 45 + React + TypeScript

- 外壳：Electron 45（Chromium 156 / Node 24.22），自带渲染引擎与 Node 主进程。
- 视图：可直接复用原型的 HTML/CSS 结构。
- 内核：Node 侧写 HTTP/DB/文件/进程。
- 播放：`<video>` + hls.js（MSE），需要时接 `electron-mpv-video`（libmpv 原生插件，Windows x64，Electron 40+）。
- 体积：安装包约 120–160 MB，空闲内存 250–400 MB。

**判断**：唯一能"原型即产品"的路线。所有 CSS 细节原样成立，内核用 JS 写，两人都能上手。

### B. Tauri 2.12 + React + Rust

- 外壳：Tauri 2.12（2026-09 发布，已放弃 Win7，MSRV Rust 1.90），用系统 WebView2。
- 视图：同样是 React + 原型 CSS，**R1 与 A 基本持平**（WebView2 是 Chromium 内核）。
- 内核：Rust。文件/进程/HTTP 都要写 Rust 或找插件。
- 体积：约 8–15 MB，空闲内存 80–150 MB。

**判断**：跑起来更轻，代价是内核要 Rust。两人若无 Rust 经验，R5 直接掉两档；播放器嵌 mpv 也比 Electron 麻烦（需要 sidecar + IPC 或窗口句柄嵌入）。

### C. Flutter 3.47 + media_kit

- 外壳：Flutter 3.47.6（Dart 3.13.5，桌面默认 Impeller）。
- 播放：media_kit + libmpv，**播放能力最强**：Anime4K、多音轨、外挂字幕开箱即用。
- 视图：**必须全部重写**。CSS 的 `mask-image`、`minmax` 网格、`backdrop-filter`、五条曲线、`offsetWidth` 强制重排的重播技巧，在 Flutter 里都要换成另一套等价物，且难以像素级对齐。

**判断**：播放最强、UI 最贵。上一版 Flutter 实现已经因为"没达到设计要求"被废弃，原因正是这条。**除非愿意放弃"原型即定稿"策略，否则不选。**

### D. .NET 9 + WebView2（WPF/WinUI 外壳）

- 外壳：C# 写窗口与系统能力，UI 仍放 WebView2 里跑 React。
- 优点：Windows 原生能力强，启动快，体积小。
- 缺点：等于"自己造一个更弱的 Electron"——桥要手写，前端工具链与 Node 生态（抓取、封面处理）用不上，两人团队开发速度最慢。

**判断**：只有"团队是 C# 背景"时才值得，本项目不是。

### E. 本地服务 + 系统浏览器

- 一个 Go/Node 服务，浏览器打开 `localhost`。
- 优点：零安装负担，跨平台白送。
- 缺点：**没有应用窗口**——做不了全屏播放器覆盖层、迷你播放条贴底、置顶、托盘；浏览器标签页会误关；写文件只能靠用户逐个选目录。

**判断**：形态不符。定稿的播放器"独立于主站""恒暗""覆盖层"这些要求，浏览器里做不到。

## 4. 决策矩阵

打分 1–5，加权后满分 100。

| 约束（权重） | A Electron | B Tauri | C Flutter | D .NET+WebView2 | E 本地服务 |
| --- | --- | --- | --- | --- | --- |
| R1 原型对齐（20） | **5** | **5** | 2 | **5** | 4 |
| R2 播放能力（18） | 4 | 4 | **5** | 4 | 3 |
| R3 本地能力（15） | **5** | 4 | 4 | 5 | 3 |
| R4 数据检索（10） | **5** | 4 | 3 | 4 | 5 |
| R5 两人速度（15） | **5** | 3 | 3 | 2 | 4 |
| R6 运行开销（7） | 2 | **5** | 4 | 5 | 3 |
| R7 生态资料（8） | **5** | 3 | 4 | 3 | 3 |
| R8 跨平台（4） | 4 | 4 | **5** | 2 | 5 |
| R9 长期维护（3） | 3 | 4 | 3 | 4 | 2 |
| **加权总分** | **90.2** | 80.8 | 70.8 | 76.2 | 72.0 |

读表要点：

- **A 与 B 的差距几乎全在 R5（两人速度）和 R7（生态）**，不在能力。若团队有 Rust 底子，B 会追到 85 以上——这时体积与内存优势才值得。
- **C 输在 R1**：不是"UI 做不出来"，是"要重做一遍且对不齐"。上一版已经验证过这个成本。
- **D 输在 R5**：手写桥 + 用不上 Node 生态，两人做不完。
- **E 输在形态**：不是技术分低，是产品做不成。

## 5. 推荐栈（D1 = Electron）

### 5.1 清单

| 层 | 选型 | 版本 | 为什么是它 | 风险 |
| --- | --- | --- | --- | --- |
| 外壳 | Electron | 45.x | 自带 Chromium + Node；渲染=原型 | 体积/内存大 |
| 构建 | electron-vite | 最新 | 主/预加载/渲染三端一套配置，HMR 完整 | 生态较新，出问题查 issue |
| 视图 | React | 19.x | 生态最全；两人都会的概率最高 | 并发特性用不上，无妨 |
| 语言 | TypeScript | 5.x（strict） | 契约层（`shared/`）靠类型守住 | — |
| 路由 | **自写 hash 路由** | — | 必须自己控 `data-anim`、`backStack`、签名去重（红线 74/77/78） | 约 200 行，值得 |
| 状态 | Zustand | 5.x | 支持选择器订阅，天然满足"局部更新"（定稿 §0.9） | 别用它管路由 |
| 样式 | **原生 CSS + 令牌变量 + CSS Modules** | — | 定稿的令牌体系必须一处生效；Tailwind 会绕开令牌 | 需要自律，靠 stylelint 兜 |
| 数据库 | better-sqlite3 | 12.x | 同步 API，事务写法最简单；WAL + FTS5 齐全 | 原生模块，打包要 rebuild |
| HTTP | undici（Node 内置 fetch） | — | 支持自定义头、流式、代理 | 需自写重试/限流 |
| HLS | hls.js | 1.x | MSE 方案成熟；可拦截分片请求 | 极端加密流需回落 mpv |
| 播放（P1） | electron-mpv-video（libmpv） | 0.1.x | Windows x64 可用，走共享纹理，能叠 HTML 控件；支持 Anime4K | 生态很新，需 spike 验证 |
| 下载 | 自写（Range + 分片 + `.part`） | — | 需求很具体（续传、并发、命名模板），现成库都不合适 | 边界多，要单测 |
| 图标 | 自绘 SVG sprite | — | 定稿要求线性图标 stroke 1.8，不允许 emoji | 工作量在画图 |
| 测试 | Vitest + Playwright | — | 单测快、E2E 能测真窗口 | Playwright 对 Electron 需 `_electron` 启动器 |
| 代码质量 | ESLint 9（flat）+ Prettier + stylelint | — | 把红线做成可执行检查 | 规则要自己写几条 |
| 打包 | electron-builder | 最新 | NSIS + portable 双产物，签名可后加 | 原生模块需在 CI 上 rebuild |
| 日志 | 自写（按天滚动） | — | 只需写文件 + 级别 | 别引入重型 logger |

### 5.2 为什么不用现成的 UI 组件库

定稿的每个控件都是"和别处不一样"的：分区条等宽、工具条一行三样、卡片两行进度、播放器两行控件。套组件库的结果是**先写一堆覆盖样式，再删掉组件库的行为**。直接用 CSS，反而更快。

### 5.3 关键版本锚点（2026-10 核对）

| 组件 | 当前稳定 | 备注 |
| --- | --- | --- |
| Electron | 45（Chromium 156 / Node 24.22） | 43/44 也在维护线 |
| Tauri | 2.12 | 已放弃 Win7，MSRV Rust 1.90 |
| Flutter | 3.47.6（Dart 3.13.5） | 桌面默认 Impeller |
| libmpv 集成 | electron-mpv-video 0.1.1 | Windows x64 / macOS arm64；需 Electron 40+ |

## 6. 可逆性：哪些决定能反悔

这是选型里最该先想清楚的东西。

| 决定 | 可逆？ | 反悔成本 |
| --- | --- | --- |
| D2 视图框架 | ✅ 高 | `src/` 重写 2–3 天（前提：视图层不写业务） |
| CSS 方案 | ✅ 高 | 半天 |
| 状态管理 | ✅ 高 | 1 天 |
| D5 分发方式 | ✅ 高 | 半天 |
| 数据库驱动 | ✅ 中 | 换驱动要改查询层，1–2 天 |
| D3 播放内核 | ✅ 中 | 有 `PlaybackSession` 接口挡着，加 adapter 2–3 天 |
| **D1 应用外壳** | ❌ **低** | 内核层（`core/`）整体重写：Tauri 要 Rust 重写全部服务，估算 3–4 周 |
| **D4 规则形态** | ❌ 低 | 规则生态与解析器全改，且已导出的规则全部作废 |

**结论**：把精力花在 D1 和 D4 上一次选对；D2/D3/D5 可以边做边换。这也是为什么本架构把外壳当"可替换件"（`02` §3.1），把领域层当资产。

## 7. 被否决的方案

| 方案 | 否决理由 | 什么情况下改判 |
| --- | --- | --- |
| Flutter 全量 | 原型 CSS 级约束要逐页重写；上一版已因此废弃 | 放弃"原型即定稿"，改由设计稿驱动 |
| .NET + WebView2 | 手写桥 + 生态错位，两人做不完 | 团队是 C# 背景 |
| 本地服务 + 浏览器 | 做不出播放器覆盖层/迷你条/托盘 | 改成"网页版"产品定位 |
| Electron + Vue | 不是不能做，是团队熟悉度未知 | 若两人都更熟 Vue，直接换，成本 2 天 |
| 纯 Web + PWA | 无法访问任意磁盘、无法启 EXE | 不做本地资源管理 |
| React Native / MAUI | 桌面端能力弱，且要重写 UI | 不做 |

## 8. 需要你拍板的决策

> **2026-10-30 更新：D1 / D2 / D3 已拍板，均按推荐方案。** 决策记录见 `docs/adr/001~003`。
> D4 按"声明式 JSON"锁定（安全原因，不开放为可选项）；D5 暂按双产物，构建时再确认。

### D1 · 应用外壳（最重要，不可逆）—— ✅ 已定：Electron 45

| 选项 | 选它的理由 | 不选它的理由 | 结论 |
| --- | --- | --- | --- |
| **Electron 45** | 原型 1:1、Node 生态、两人都能写、libmpv 有现成插件 | 安装包 130 MB+，内存 300 MB+ | **采用** |
| Tauri 2.12 | 体积 10 MB、内存 1/3、Rust 安全 | 内核要 Rust；mpv 嵌入更麻烦；生态少 | 备选，不采用 |

> 判据（已确认）：两人无 Rust 实战经验 → Electron。体积与内存代价已接受。

### D2 · 视图框架 —— ✅ 已定：React 19

| 选项 | 说明 | 结论 |
| --- | --- | --- |
| **React 19** | 生态最大，选择器订阅满足局部更新 | **采用** |
| Vue 3 | 模板更接近原型 HTML | 不采用 |
| Svelte 5 | 运行时最轻，生态需自补 | 不采用 |

### D3 · 播放内核 —— ✅ 已定：`<video>` + hls.js 优先，P1 加 libmpv

| 选项 | 说明 | 结论 |
| --- | --- | --- |
| **`<video>` + hls.js 优先** | 1 周内能播；覆盖绝大多数源；弹幕用 DOM 叠层 | **采用** |
| libmpv 优先 | 画质/字幕/音轨一步到位，起播晚 2 周 | P1 作为 `mpv-adapter` 接入 |

### D4 · 规则形态 —— ✅ 已锁定：声明式 JSON

| 选项 | 说明 | 结论 |
| --- | --- | --- |
| **声明式 JSON**（specVersion 1） | 可导入/分享/单测；远程规则不能变远程代码 | **锁定，不作为可选项** |
| 可执行脚本 | 表达力强，但"从链接导入规则"= 允许任何人往你机器上跑代码 | 禁止 |

### D5 · 分发 —— 暂定：NSIS 安装版 + 便携 zip

| 选项 | 说明 | 结论 |
| --- | --- | --- |
| **NSIS + 便携 zip** | 便携版放 U 盘/网盘，数据目录跟着走 | 暂定，M5 前确认 |
| 仅便携 | 少一个产物，首次运行需手动处理运行时 | 不采用 |

## 9. 选型后的风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Electron 包体大、启动慢 | 首次体验差 | 拆首屏、骨架屏、封面懒加载；启动打点卡 2.5 s |
| better-sqlite3 原生模块打包失败 | 装完打不开库 | CI 上 `electron-rebuild`；产物在干净虚拟机验证 |
| hls.js 遇到加密流播不了 | 部分源不可用 | 明确报 `E_DRM_UNSUPPORTED`，不留白屏；P1 上 mpv |
| 源站改版导致规则集体失效 | 核心功能瘫痪 | 健康度看板 + 规则版本化 + 导入/导出 + 失败可见 |
| libmpv 插件生态太新 | P1 卡住 | 先做 spike（2 天）验证 Windows 嵌入与打包，不行就退回 `<video>` |
| 两人对契约理解不一致 | 合并即冲突 | `shared/` 快照测试（`04` §10） |

## 10. 落地第一步（选型确认后 3 天）

1. **Spike-1（0.5 天）**：`electron-vite` 起空壳，把 `prototype/` 的 `index.html + style.css` 原样塞进 `src/`，确认五条动效与 Hero 三段式在 Electron 里表现一致（重点验 `backdrop-filter` 与 `mask-image`）。
2. **Spike-2（1 天）**：better-sqlite3 建库、跑 V001 迁移、读 78 部演示数据渲出首页，测冷启动与滚动帧率。
3. **Spike-3（1 天）**：用一个真实源，手工跑通"搜索 → 详情 → m3u8 → 本地代理 → `<video>` 播放"。**这一步过了，项目才真的成立。**
4. **Spike-4（0.5 天）**：`electron-builder` 出 NSIS 包，在干净 Windows 上装一次。

四个 spike 全过 → 按 `06-开发规范.md` 开工；任一不过 → 回来重看本文件的对应章节。
