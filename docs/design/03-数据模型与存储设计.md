# 03 · 数据模型与存储设计

> 版本 v1.0 · 2026-10-30
> 上位文档：[设计定稿 v3.3](../ACGN聚合软件-设计定稿.md) §3 / §3.1 · [需求规格说明书](01-需求规格说明书.md)
> 原则：**只存"读到哪"，不存"读到百分之几"**。百分比是派生值，存进库就会和真实位置对不上（定稿 §3 第 5 条）。

---

## 1. 存储选型

| 数据 | 存哪 | 为什么不 |
| --- | --- | --- |
| 作品 / 系列 / 进度 / 下载 / 资源索引 | **SQLite（WAL）** | 需要事务、外键、全文检索、几万行级查询 |
| 封面图 | 文件系统 `covers/<id>.jpg` | 460×650 约 60–120 KB，进 BLOB 会把库撑到 GB 级，且备份变慢 |
| 刮削原文 | 文件系统 `cache/scrape/<hash>.json` | 原文可能几十 KB，只需按需回看 |
| HLS 临时分片 | 文件系统 `cache/hls/` | 定时清理，不进库 |
| 设置 | SQLite `kv` 表 | 比 JSON 文件好处：和业务同事务、可迁移、可查询 |
| 日志 | 文件 | 需要按天滚动与外部工具查看 |
| 自定义封面（典藏） | 库内 TEXT（400×600 压缩后 dataURL ≈ 60–120 KB） | 定稿明确要求压到 400×600，量小且必须随库迁移 |

> **不选 IndexedDB**：删库/清缓存后用户作品区会全丢；也没法用 SQL 做分组统计。
> **不选 JSON 全量文件**：每次写要重写整个文件，进度这种高频小写入会把盘写坏。

---

## 2. 概念模型

```
series 1 ────< works >──── work_tags >──── tags
                 │
                 ├──< episodes ──< ep_sources >── rules
                 ├──< volumes ──< chapters
                 ├──< tracks                （仅音乐）
                 ├──1 game_info             （仅游戏）
                 ├──1 reading_position      （唯一进度真相）
                 ├──< credits               （制作 / 声优）
                 ├──< work_relations        （关联作品，双向）
                 └──< history
downloads ──< download_items ──(episode_id)
resource_roots ──< resource_files
```

**没有 `progress` 表**。进度 = `reading_position` 的一行 + 运行时派生。

## 3. 表结构（DDL）

> 约定：时间一律 `INTEGER` 存 Unix 毫秒；布尔用 `INTEGER 0/1`；主键用业务 id（TEXT）便于规则与外部源对齐。

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA synchronous = NORMAL;

-- ---------- 元信息 ----------
CREATE TABLE schema_meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);  -- 存 schema_version / app_version / last_migrated_at

-- ---------- 系列 ----------
CREATE TABLE series (
  id          TEXT PRIMARY KEY,            -- 'fate'
  name        TEXT NOT NULL,               -- 'Fate'
  since_year  INTEGER,
  intro       TEXT DEFAULT '',
  order_note  TEXT DEFAULT '',             -- 「怎么看这个系列」人工维护
  cover_path  TEXT,                        -- 自定义封面 dataURL 或文件路径
  is_custom   INTEGER NOT NULL DEFAULT 0,  -- 自建典藏
  hidden      INTEGER NOT NULL DEFAULT 0,  -- 管理态「移除」只置 1，不删
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);

-- ---------- 作品 ----------
CREATE TABLE works (
  id           TEXT PRIMARY KEY,           -- 'aot' / 'lisa_oath'
  kind         TEXT NOT NULL CHECK (kind IN ('anime','game','manga','novel','music')),
  name         TEXT NOT NULL,              -- 原名（混合列表下才带「（漫画）」后缀）
  display_name TEXT NOT NULL,              -- 去掉后缀后的展示名
  year         INTEGER,
  quarter      INTEGER,                    -- 1..12，季度首发月
  status       TEXT CHECK (status IN ('连载','完结') OR status IS NULL),
  form         TEXT CHECK (form IN ('剧场版','TV','OVA','单曲专辑','专辑','OST','同人专辑','广播剧') OR form IS NULL),
  og           TEXT NOT NULL DEFAULT '' CHECK (og IN ('','原作','原创','漫画改','轻小说改','游戏改','小说改')),
  accent       TEXT NOT NULL DEFAULT '#6E675F',
  intro        TEXT NOT NULL DEFAULT '',
  cover_path   TEXT,                       -- covers/<id>.jpg，缺失时回落渐变
  series_id    TEXT REFERENCES series(id) ON DELETE SET NULL,
  score        REAL,                       -- 媒体分，一位小数，只读
  score_src    TEXT,                       -- 'Bangumi' / 'AniList'
  votes        INTEGER,                    -- 样本量；score 与 votes 必须同时有值才允许显示
  artist       TEXT,                       -- 仅音乐：'LiSA / Aimer'
  album_type   TEXT,                       -- 仅音乐：等同 form，冗余存一份便于筛选
  in_shelf     INTEGER NOT NULL DEFAULT 0, -- 是否在作品区
  shelf_added  INTEGER,                    -- 加入作品区时间
  local        INTEGER NOT NULL DEFAULT 0, -- 是否有本地资源（详情页标"已缓存本地"）
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  CHECK (score IS NULL OR votes IS NOT NULL)   -- 没样本量就不许有均分
);
CREATE INDEX idx_works_kind_year ON works(kind, year DESC);
CREATE INDEX idx_works_shelf     ON works(in_shelf, kind, shelf_added DESC);
CREATE INDEX idx_works_series    ON works(series_id);

-- ---------- 标签 ----------
CREATE TABLE tags (
  id   INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE
);
CREATE TABLE work_tags (
  work_id TEXT NOT NULL REFERENCES works(id) ON DELETE CASCADE,
  tag_id  INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (work_id, tag_id)
);
CREATE INDEX idx_work_tags_tag ON work_tags(tag_id);

-- ---------- 制作 / 声优（统一一张表，用 role_type 区分） ----------
CREATE TABLE credits (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  work_id   TEXT NOT NULL REFERENCES works(id) ON DELETE CASCADE,
  role_type TEXT NOT NULL CHECK (role_type IN ('production','cast')),
  role      TEXT NOT NULL,   -- '监督' / '冈部伦太郎'
  name      TEXT NOT NULL,   -- '佐藤卓哉' / '宫野真守'
  ord       INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_credits_work ON credits(work_id, role_type, ord);

-- ---------- 剧集（动漫） ----------
CREATE TABLE episodes (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  work_id  TEXT NOT NULL REFERENCES works(id) ON DELETE CASCADE,
  n        INTEGER NOT NULL,      -- 第几集；游戏=1（"启动"）
  title    TEXT DEFAULT '',
  air_at   INTEGER,               -- 播出时间，时间表用
  dur_sec  INTEGER,
  local    INTEGER NOT NULL DEFAULT 0,
  UNIQUE (work_id, n)
);
CREATE INDEX idx_eps_work ON episodes(work_id, n);

-- ---------- 卷 / 话（漫画、轻小说） ----------
CREATE TABLE volumes (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  work_id TEXT NOT NULL REFERENCES works(id) ON DELETE CASCADE,
  n       INTEGER NOT NULL,
  name    TEXT DEFAULT '',
  cover_path TEXT,
  UNIQUE (work_id, n)
);
CREATE TABLE chapters (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  volume_id INTEGER NOT NULL REFERENCES volumes(id) ON DELETE CASCADE,
  n         INTEGER NOT NULL,
  title     TEXT DEFAULT '',
  UNIQUE (volume_id, n)
);

-- ---------- 曲目（音乐） ----------
CREATE TABLE tracks (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  work_id TEXT NOT NULL REFERENCES works(id) ON DELETE CASCADE,
  n       INTEGER NOT NULL,
  title   TEXT NOT NULL,
  dur_sec INTEGER NOT NULL,     -- 由 'm:ss' 解析而来，禁止存字符串
  UNIQUE (work_id, n)
);

-- ---------- 游戏属性 ----------
CREATE TABLE game_info (
  work_id      TEXT PRIMARY KEY REFERENCES works(id) ON DELETE CASCADE,
  platform     TEXT,            -- 'PS5' / 'PC'
  release_at   INTEGER,
  languages    TEXT,            -- '简中 / 日文'
  dlc          TEXT,            -- '含 3 个 DLC'
  achievements INTEGER,
  play_status  TEXT CHECK (play_status IN ('在玩','已通关','想玩','搁置'))
);

-- ---------- 进度（唯一真相） ----------
CREATE TABLE reading_positions (
  work_id    TEXT PRIMARY KEY REFERENCES works(id) ON DELETE CASCADE,
  at         INTEGER NOT NULL DEFAULT 0,  -- 第几集 / 第几卷
  ch         INTEGER,                     -- 章节内第几话/章（漫画/小说）
  ch_of_vol  INTEGER,                     -- 当前卷共几话/章，用于卷内百分比
  done       INTEGER NOT NULL DEFAULT 0,  -- 只由显式操作置 1，绝不反推
  updated_at INTEGER NOT NULL
);
-- 动漫：pct = at/total
-- 漫画/小说：pct = (at-1 + ch/ch_of_vol)/total，夹 1..100
-- 游戏/音乐：无 progress，本表无行

-- ---------- 源规则 ----------
CREATE TABLE rules (
  id           TEXT PRIMARY KEY,      -- 'builtin-a'
  name         TEXT NOT NULL,
  version      TEXT NOT NULL DEFAULT '1.0.0',
  partition    TEXT,                  -- 主要覆盖的介质，可空=通用
  origin       TEXT NOT NULL CHECK (origin IN ('builtin','imported')),
  source_url   TEXT,                  -- 从链接导入时留档
  spec_json    TEXT NOT NULL,         -- 规则原文，校验后才落库
  enabled      INTEGER NOT NULL DEFAULT 1,
  health       REAL NOT NULL DEFAULT 1.0,   -- 0..1，滑动平均
  ok_count     INTEGER NOT NULL DEFAULT 0,
  fail_count   INTEGER NOT NULL DEFAULT 0,
  last_ok_at   INTEGER,
  last_err     TEXT,
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);

-- ---------- 每集候选源（集数拼图的落点） ----------
CREATE TABLE ep_sources (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  episode_id  INTEGER NOT NULL REFERENCES episodes(id) ON DELETE CASCADE,
  rule_id     TEXT NOT NULL REFERENCES rules(id) ON DELETE CASCADE,
  page_url    TEXT NOT NULL,
  play_url    TEXT,                   -- 解析后的 m3u8/mp4，可缓存
  quality     TEXT,                   -- '1080P'
  latency_ms  INTEGER,
  ok          INTEGER NOT NULL DEFAULT 0,
  last_check  INTEGER,
  UNIQUE (episode_id, rule_id)
);

-- ---------- 更新（作品区「有更新」筛选依据） ----------
CREATE TABLE work_updates (
  work_id    TEXT PRIMARY KEY REFERENCES works(id) ON DELETE CASCADE,
  latest_at  INTEGER,
  latest_no  INTEGER,                -- 最新一集/一卷
  seen_no    INTEGER,                -- 用户已看到的最大编号
  unread     INTEGER NOT NULL DEFAULT 0
);

-- ---------- 关联作品（手写或刮削） ----------
CREATE TABLE work_relations (
  work_id   TEXT NOT NULL REFERENCES works(id) ON DELETE CASCADE,
  target_id TEXT NOT NULL,     -- 允许指向未入库作品（只有名字）
  target_name TEXT,
  rel_type  TEXT NOT NULL,     -- '同系列' / '改编自' / '续作'
  PRIMARY KEY (work_id, target_id)
);

-- ---------- 下载 ----------
CREATE TABLE downloads (
  id         TEXT PRIMARY KEY,
  work_id    TEXT REFERENCES works(id) ON DELETE SET NULL,
  name       TEXT NOT NULL,
  kind       TEXT NOT NULL,
  target_dir TEXT NOT NULL,
  status     TEXT NOT NULL CHECK (status IN ('queued','running','paused','done','failed')),
  total_items INTEGER NOT NULL DEFAULT 0,
  done_items  INTEGER NOT NULL DEFAULT 0,
  err_code   TEXT,
  err_msg    TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE download_items (
  id           TEXT PRIMARY KEY,
  download_id  TEXT NOT NULL REFERENCES downloads(id) ON DELETE CASCADE,
  episode_id   INTEGER,
  n            INTEGER NOT NULL,
  url          TEXT NOT NULL,
  target_path  TEXT NOT NULL,
  status       TEXT NOT NULL CHECK (status IN ('queued','running','paused','done','failed')),
  bytes_done   INTEGER NOT NULL DEFAULT 0,
  bytes_total  INTEGER NOT NULL DEFAULT 0,
  seg_done     INTEGER NOT NULL DEFAULT 0,
  seg_total    INTEGER NOT NULL DEFAULT 0,
  speed_bps    INTEGER NOT NULL DEFAULT 0,
  attempts     INTEGER NOT NULL DEFAULT 0,
  err_msg      TEXT,
  updated_at   INTEGER NOT NULL
);
CREATE INDEX idx_dli_download ON download_items(download_id, n);

-- ---------- 资源 ----------
CREATE TABLE resource_roots (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  path     TEXT NOT NULL UNIQUE,
  label    TEXT,
  type     TEXT CHECK (type IN ('local','removable','network')),
  enabled  INTEGER NOT NULL DEFAULT 1,
  scanned_at INTEGER
);

CREATE TABLE resource_files (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  root_id    INTEGER NOT NULL REFERENCES resource_roots(id) ON DELETE CASCADE,
  rel_path   TEXT NOT NULL,
  is_dir     INTEGER NOT NULL DEFAULT 0,
  kind       TEXT,              -- 识别出的分区；未识别为 NULL
  work_id    TEXT,              -- 识别出的作品；未识别为 NULL
  size       INTEGER NOT NULL DEFAULT 0,
  mtime      INTEGER,
  ignored    INTEGER NOT NULL DEFAULT 0,
  UNIQUE (root_id, rel_path)
);
CREATE INDEX idx_rf_parent ON resource_files(root_id, rel_path);
CREATE INDEX idx_rf_work   ON resource_files(work_id);

-- ---------- 磁盘读数缓存 ----------
CREATE TABLE disks (
  id         TEXT PRIMARY KEY,   -- 卷标/挂载点
  name       TEXT NOT NULL,
  type       TEXT NOT NULL,
  total      INTEGER,
  free       INTEGER,
  by_kind    TEXT,               -- JSON: {"anime":123456,...}
  measured_at INTEGER
);

-- ---------- 历史 ----------
CREATE TABLE history (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  work_id TEXT NOT NULL REFERENCES works(id) ON DELETE CASCADE,
  view    TEXT NOT NULL,        -- 'detail' / 'player' / 'reader'
  at      INTEGER NOT NULL
);
CREATE INDEX idx_history_at ON history(at DESC);

-- ---------- 刮削缓存 ----------
CREATE TABLE scrape_cache (
  work_id    TEXT NOT NULL,
  provider   TEXT NOT NULL,      -- 'bangumi' / 'moegirl'
  payload    TEXT NOT NULL,      -- 原文 JSON
  fetched_at INTEGER NOT NULL,
  ttl_sec    INTEGER NOT NULL DEFAULT 604800,
  PRIMARY KEY (work_id, provider)
);

-- ---------- 设置 ----------
CREATE TABLE kv (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL,          -- JSON 编码
  updated_at INTEGER NOT NULL
);
```

### 3.1 全文检索

```sql
-- trigram 分词对中文子串友好（SQLite 3.34+）
CREATE VIRTUAL TABLE works_fts USING fts5(
  name, display_name, intro, tags,
  content='', tokenize='trigram'
);
```

| 查询长度 | 策略 |
| --- | --- |
| ≥3 字 | `works_fts MATCH`，返回 rank |
| 1–2 字 | trigram 无法命中，回落 `name LIKE 'x%'`（走索引前缀） |
| 空 | 不出结果，只显示搜索历史 |

写入时机：`works` 插入/更新后由 `library` 同步一行，**不许**在视图层直接写 FTS 表。

## 4. 派生规则（代码里，不在库里）

| 派生值 | 公式 | 边界 |
| --- | --- | --- |
| `total` | 动漫 = `COUNT(episodes)`；漫画/小说 = `COUNT(volumes)`；音乐 = `COUNT(tracks)` | 游戏 = 无 |
| `progress.pct` | 动漫 `at/total`；漫画/小说 `(at-1 + ch/ch_of_vol)/total` | 夹在 1–100；`done=1` 时写"已看完"不写 100%；游戏/音乐 = null |
| `albumDur` | `SUM(tracks.dur_sec)` | ≥3600 写「1 小时 12 分」 |
| `countOf` | 音乐返回曲目数，其余返回集/卷数 | 单位见定稿 §3.1 |
| `originText` | `og` 六值映射 | 空值不带 chip |
| `fmtCount` | <10000 写准确值，≥10000 写「万」 | 定稿红线 91 |
| `health` | `0.7*近20次成功率 + 0.3*(1 - 归一化延迟)` | 只用于排序，不显示数字 |

**禁止**：在库里存 `pct`、`shelfProg` 文本、"43 分钟"死数字、任何"已看完"的布尔冗余（`done` 已经有了）。

## 5. 典型查询

```sql
-- 5.1 分类页：某介质某年份段，按评分降序，分页 30
SELECT w.* FROM works w
WHERE w.kind = ? AND w.year BETWEEN ? AND ?
ORDER BY w.score DESC NULLS LAST, w.year DESC
LIMIT 30 OFFSET ?;

-- 5.2 作品区：我的追番 + 筛选「在看」+ 排序「最近观看」
SELECT w.*, rp.at, rp.ch, rp.ch_of_vol, rp.done
FROM works w
JOIN reading_positions rp ON rp.work_id = w.id
WHERE w.in_shelf = 1 AND w.kind = 'anime'
  AND rp.done = 0
ORDER BY rp.updated_at DESC;

-- 5.3 题材分组：取当前分区前 4 个高频题材，每组 6 部
SELECT t.name, COUNT(*) c FROM work_tags wt
JOIN tags t ON t.id = wt.tag_id
JOIN works w ON w.id = wt.work_id
WHERE w.kind = ?
GROUP BY t.id HAVING c >= 3 ORDER BY c DESC LIMIT 4;

-- 5.4 某集候选源，按健康度排
SELECT es.*, r.health FROM ep_sources es
JOIN rules r ON r.id = es.rule_id
WHERE es.episode_id = ? AND r.enabled = 1
ORDER BY es.ok DESC, r.health DESC, es.latency_ms ASC;
```

**性能守则**：列表查询不许 `SELECT *` 加三次子查询算进度；`episodes`/`tracks` 数量大的表只查需要的列。

## 6. 迁移

| 项 | 规则 |
| --- | --- |
| 版本位 | `PRAGMA user_version` + `schema_meta.schema_version` 双写 |
| 迁移文件 | `core/db/migrations/V001__init.sql`、`V002__add_xxx.sql`，**只增不改** |
| 执行 | 启动时读 `user_version`，逐个执行大于它的脚本，全程包在一个事务里 |
| 备份 | 迁移前把 `kaede.db` 复制为 `backups/kaede-<ver>-<ts>.db`，保留最近 3 份 |
| 失败 | 回滚事务 → 用备份覆盖 → 提示"数据未升级，已回退"，不许带着半升级的库继续跑 |
| 兼容 | 只做向前迁移。**不写降级脚本**（降级靠备份） |
| 测试 | `tests/unit/migration.test.ts` 用 V1 数据跑全链路，断言行数与派生值不变 |

## 7. 本地文件布局

```
%APPDATA%/Kaede/
├─ kaede.db            (+ -wal / -shm)
├─ covers/<workId>.jpg          作品封面（460×650）
├─ series/<seriesId>.jpg        系列海报（可选）
├─ cache/
│  ├─ scrape/<sha1>.json        刮削原文
│  ├─ hls/<sessionId>/          播放临时分片（退出即清）
│  └─ img/<sha1>.webp           缩略图
├─ rules/                       用户导入的规则（与库内 spec_json 同步）
├─ backups/
└─ logs/kaede-YYYYMMDD.log
```

资源目录（用户自选，U 盘/NAS 同理）：

```
<root>/
├─ 动漫/<作品名>/Season 1/<作品名> - S01E01.mkv
├─ 游戏/<作品名>/...
├─ 漫画/<作品名>/第 01 卷/...
├─ 轻小说/<作品名>/第 01 卷/...
└─ 音乐/<专辑名>/01 - 曲名.flac
```

命名模板（设置页可改，默认）：

| 介质 | 模板 | 示例 |
| --- | --- | --- |
| 动漫 | `{name}/Season {season:00}/{name} - S{season:00}E{ep:00}` | `葬送的芙莉莲/Season 1/葬送的芙莉莲 - S01E05.mkv` |
| 漫画 | `{name}/第 {vol:00} 卷/{name} - 第 {ch:000} 话` | |
| 小说 | `{name}/第 {vol:00} 卷/{name} - 第 {ch:000} 章` | |
| 音乐 | `{album}/{n:00} - {title}` | |

**非法字符**：`\ / : * ? " < > |` 与结尾空格点号一律替换为 `_`；Windows 保留名（CON/PRN/AUX/NUL/COM1…）前加 `_`。

## 8. 一致性与写入策略

| 场景 | 策略 |
| --- | --- |
| 进度写入 | 内存里 5 s 节流合并，`pause`/`unload`/`切集` 强制 flush；一次事务只写一行 |
| 作品入库 | `works` + `tags` + `episodes` + `reading_positions` 同一事务 |
| 批量删除 | 单事务；`resource_files` 用 `ON DELETE CASCADE` 随根删除 |
| 并发写入 | 只有主进程一个连接；worker 通过消息请求写，不自己开库 |
| 读取隔离 | WAL 下读不阻塞写；长查询（统计）走只读事务 |

## 9. 容量估算

| 对象 | 单条 | 数量 | 占用 |
| --- | --- | --- | --- |
| works | ~1.2 KB | 10,000 | 12 MB |
| episodes | ~80 B | 300,000 | 24 MB |
| tracks | ~60 B | 50,000 | 3 MB |
| ep_sources | ~200 B | 900,000 | 180 MB（需定期清理失败项） |
| resource_files | ~150 B | 200,000 | 30 MB |
| FTS 索引 | — | — | ~15 MB |
| 封面文件 | 90 KB | 10,000 | 900 MB（可按需清理 LRU） |

→ **库控制在 300 MB 内**，封面另算。`ep_sources` 是唯一会失控的表：保留策略 = 每集最多 5 条 + 失败且 30 天未成功的删除。

## 10. 备份与导出

> **2026-10-30 增补（v1 需求）**：你在 `08` E3 明确「**需要自动备份**」，H3 / E2 定备份目标是**本地目录**、不用 WebDAV。因此下面「自动备份」从无到有，进 v1。

| 形式 | 内容 | 时机 | 用途 |
| --- | --- | --- | --- |
| **周期性自动备份** | 复制 `kaede.db`（WAL checkpoint 后）到用户指定本地目录 | 每日首次启动 + 每 N 次写入触发一次（N 默认 50），保留最近 **7 份**滚动 | **v1**：防进度/作品区/下载记录丢失 |
| 迁移前自动备份 | 同上 | 每次 schema 迁移前（已有） | 迁移失败可回滚 |
| 全量备份（手动） | 同上 | 用户手动 | 换机 |
| 数据导出 | JSON：作品区 / 进度 / 典藏 / 设置 | 手动 | 换机、分享（P1） |
| 规则导出 | 规则包 zip（`rules/*.json` + manifest） | 手动 | 定稿 §5.1 P1 |

约束：

- **备份目录由用户在设置里指定**，默认放在应用数据目录下的 `backups/`；**不写 `%APPDATA%` 以外的位置**（便携版另议，见 `08` H5）。
- 备份文件名带时间戳与 schema 版本：`kaede-20261030-1530-sv7.db`。
- **恢复要能选某一份**，且恢复前自动再备份一次当前库（防止恢复错版本）。
- 备份失败**必须可见**（进度条旁标红 + 明确文案），不许静默（`01` §6.3 / 定稿 §0.12）。
- 作品关系表（`work_relation`，见 §2）随库一起备份；它是 H2 定的后台数据，无前台入口。

**不做**：把封面打进备份包（体积太大）。恢复后封面按需重抓。**不做** WebDAV / 云同步（`08` E2）。

## 11. 自查清单

1. 有没有哪张表存了"百分比""已看完"这类派生值？→ 有就是错。
2. 新增字段有没有给默认值？老库升级时 `ALTER TABLE ADD COLUMN` 必须带默认。
3. 新增查询走没走索引？`EXPLAIN QUERY PLAN` 里出现 `SCAN` 就要想。
4. 删除路径有没有 `CASCADE`？删作品留下孤儿 `episodes` 是最常见的脏数据来源。
5. 有没有把封面 BLOB 塞进库？→ 禁止。
