# ADR-007 · v1 范围与「禁止假交互」红线豁免

- 状态：✅ 已接受（2026-10-30，依据 [08 需求提问文档](08-需求提问文档.md) §7 C-6 乙、C-3 甲 你的答复）
- 关联：定稿 §8（评审方法）、定稿 §9（待做清单，新增 §9.0 豁免登记）、[09 第一版范围](09-第一版范围与迭代计划.md)

## 背景

定稿 §8 末句明确：**假交互（点了没反应）禁止**；定稿 §9 列了 13 项「本轮不实现」。

但 v1 阶段你确认的需求是：
- 界面五分区**全站 1:1 还原**（B1 / B3 / §3-1）；
- 只有**动漫分区**是真能力，游戏 / 漫画 / 小说 / 音乐分区**有界面、无真能力**（B1「不要求阅读器/音乐播放器」、D4 游戏留 P1）；
- 评论做**第三方只读聚合**，不做自己的社区（C-3 甲，推翻定稿 §9 #1「暂缓未采用」）。

于是产生两条与原定稿的冲突，必须显式裁决，否则开发会照着红线写、把四个分区入口砍掉或留假按钮。

## 选项

1. **甲**：v1 只上线动漫分区入口，其余四分区不进导航 —— 保红线，但五分区结构与 1:1 还原被打折扣。
2. **乙（已选）**：五分区页面全保留；未实现动作统一给明确的「功能未开放」提示，并在定稿 §9.0 登记 v1 豁免。
3. **丙**：把阅读器 / 音乐也做进 v1 —— 扩大范围，与 B1「不要求」相左。

## 决定

**选 乙**，并据此在定稿 §9.0 登记两项豁免：

- **H1 · 假交互豁免**：未实现动作一律给「功能未开放」提示（按钮就位 + 点击 toast 说明），不视为「点了没反应」。每处须登记本表并注明分区，**不得出现第二处未登记项**。
- **H2 · 评论豁免**：定稿 §9 #1 由「暂缓未采用」改为「v1 做第三方评论只读聚合，不做我的评分与发帖」。

## 后果

- v1 是全站界面 + 单分区真能力的「可演示完整软件」，不是「每个分区都能用」。这一点必须在交付说明里写清楚，避免朋友拿到后以为游戏/音乐能用。
- 后续迭代（S5 之后）按「用起来 → 补能力」推进：阅读器、音乐、游戏、弹幕依次从「功能未开放」转为真能力，每转一项就删掉对应豁免登记。
- 红线本身不变：已实现的动作仍不许假交互；豁免只覆盖「v1 明确不做的能力」。
