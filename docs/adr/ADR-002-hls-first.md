# ADR-002 · 播放内核先用 `<video>` + hls.js，libmpv 留到 P1

- **状态**：已采纳
- **日期**：2026-10-30
- **影响面**：`core/player`、播放器视图

## 背景

核心功能是"点进去就能看"。播放链路有三个必须解决的问题：

1. 源站要求 `Referer` / `UA`，首页 m3u8 拿到了，分片却 403；
2. m3u8 里是相对路径 + 一次性 token，`<video>` 拼不出来；
3. 跨域，渲染进程直连源站被 CORS 拦。

这三件事与"用哪个解码器"无关，都属于**地址与请求头翻译**，必须在主进程的本地代理里做。

## 选项

| 方案 | 起播时间 | 画质/字幕/音轨 | 嵌入成本 |
| --- | --- | --- | --- |
| `<video>` + hls.js + 本地代理 | 1 周内可跑通 | 基础（MSE 能播的都行） | 无 |
| libmpv（`electron-mpv-video`） | 晚约 2 周 | Anime4K、多音轨、外挂字幕开箱 | 原生插件 + 打包 + 共享纹理 |

## 决定

- **P0**：`<video>` + hls.js，配本地 HTTP 代理（`127.0.0.1:<随机端口>/p/<token>/…`）。
- **P1**：加 `mpv-adapter`，与 `html5-adapter` 实现同一个 `PlaybackSession` 接口。
- 播放器视图**只认 `PlaybackSession`**，不认具体内核。

代理要改写四类地址：master 的 variant、普通分片、`#EXT-X-KEY:URI`、`#EXT-X-MAP:URI`（详见 `07` §1.3）。

## 后果

**好的**：

- 第一周就能验证"这条路走不走得通"，项目风险提前暴露。
- 弹幕用 DOM 叠层，天然与视频层解耦。
- 画质增强不是 P0，晚做不阻塞主闭环。

**代价**：

- 遇到加密流（Widevine / 自定义 AES）播不了。处理方式是**明确报 `E_DRM_UNSUPPORTED`**，不留白屏，P1 交给 mpv。
- 起播依赖代理的零拷贝转发，代理写不好会成为瓶颈（`02` §12 有打点要求）。

**可逆性**：中。因为接口已经隔离，加 adapter 约 2–3 天；但要先完成 libmpv 的 spike（Windows 嵌入 + 打包 + 干净机器验证）。
