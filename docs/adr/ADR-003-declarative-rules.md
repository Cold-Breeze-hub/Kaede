# ADR-003 · 源规则锁定为声明式 JSON，不允许可执行脚本

- **状态**：已采纳（作为安全底线，不作为可选项）
- **日期**：2026-10-30
- **影响面**：`core/source`、规则生态、导入/备份功能

## 背景

源引擎需要"规则可导入/备份/分享"（定稿 §5.1）。用户会从文件、剪贴板、链接导入规则——**这意味着规则来自外部，且用户不会逐行阅读**。

如果规则里能写 JavaScript，那么"导入一条规则"等价于"允许规则作者在本机执行任意代码"，能读文件、能发请求、能起进程。

## 选项

| 方案 | 表达力 | 安全 | 可测试性 |
| --- | --- | --- | --- |
| 可执行脚本（`eval` / `new Function` / `vm`） | 最强 | **不可控** | 差（依赖网络与运行时） |
| 沙箱脚本（isolated-vm） | 强 | 依赖沙箱不逃逸，历史上多次被打穿 | 中 |
| 声明式 JSON（选择器 + 正则 + 路径） | 覆盖多数站点 | 无代码执行面 | 好（可录制回放单测） |

## 决定

采用**声明式 JSON**，`specVersion: 1`。

- 只允许四种原语：CSS 选择器、XPath、JSONPath、正则捕获。
- 变换链只有 `trim / url / number / int / date / atob / regex / json / join / default / slice`。
- **禁止** `eval`、`new Function`、`vm`、`Function` 构造；正则限长 500 且禁嵌套量词（防回溯炸弹）。
- 写不出来的站点，做**内置适配器**（代码进仓库、进评审），不走规则。

## 后果

**好的**：

- 导入规则不再有远程代码执行风险。
- 解析器可以完全离线单测：录下真实响应，断言抽取结果（`06` §7.3）。
- 规则坏了只影响一条源，不会让进程崩。

**代价**：

- 极少数站点（需要签名算法、多步 token 换取）用规则写不出来，只能进内置适配器。
- 规则作者的学习成本比"随手写段 JS"高一点，但有 `04` §4 的字段表与示例兜底。

**兼容性**：Kazumi 的规则也是 JSON，计划写 `kazumi2v1.ts` 做字段映射（P1），不做运行时双解析。
