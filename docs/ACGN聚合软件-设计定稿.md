## 0. 设计铁律（最高优先级，违反即返工）

以下 14 条来自用户的明确要求与多轮否决，**任何后续设计、开发、评审都先过这一层**。

### 0.1 一个界面只干这个界面的活

每个界面都要**自闭环**：属于这个界面的事，就在这个界面做完，不留到别的界面去补。

- 切源在播放器里做完，不在详情页显示"几个源"；
- 播放进度在详情页/作品区看得见，不用回作品区才知道看到哪；
- 资源增删在资源管理里做完，不在"我的"首页再摆一份存储占用。

### 0.2 不出现无效信息

凡是**用户已经知道、或与当前页面职责无关**的信息，一律删掉。典型：

- 分区已决定介质，列表/卡片就**不再标注"动漫/漫画/小说"**；
- 上方已经写了年份，下方不再写"2021 年放送"；
- 底部导航已写"典藏"，页面里不再来一个"典藏"大标题；
- 题材分组里的作品不再重复显示该组的题材标签。

### 0.3 不做重复功能

同一个能力只能有一个入口。**一个入口两处出现 = 直接删一处**。典型：

- 主题切换只在「设置」，顶栏不许再有主题按钮；
- 播放/弹幕/通知只在「我的 · 偏好」，设置页不再列一遍；
- "最近使用"属于浏览历史，我的页不再单独做一条；
- 版本号与本地资源数属于「关于 / 资源管理」，头像旁不再写。

### 0.4 不写解释性文字

- 页面标题下不许有副标题式的说明（"纯作品目录""整季队列·断点续传""跨介质追更，进度统一"）；
- 不写宣传语、不写设计备注（"P0 项""灰色地带全盘接受"）；
- 演示态尽量不出现"（演示）"字样，改用真实交互或干脆不显示。

**2026-10-30 划清边界（这条被反复踩）**：

- **允许**：一句纯技术说明「演示数据，不会真的保存」——它防止用户把演示当成品，属于免责而非解说；
- **禁止**：「按故事归属聚合，不是按介质」「自建典藏可以把不同介质、不同系列的作品收到一起」「全部数据只存在这台设备」「跨介质一站式收藏」这类**解释功能是什么、为什么这样设计**的文字。
  用户点进来是来用的，不是来读说明书的。**功能靠结构自解释，不靠文案补**：如果一块界面需要一句话才说得清，那是结构没做对。

### 0.5 状态标签一律不用

**"追更中 / 看一半 / 已看完 / 已通关"这类状态标签已被彻底否决**，不得以任何形式复活：

- 作品区不按状态分组、不排序、不显示状态标签；
- 典藏不显示是否在追/是否看完、不显示进度条；
- 作品区只显示**进度文字**（看到第几集/第几卷）——这是位置，不是状态。

**2026-10-30 定界**：本条约束的是**有位置可标的介质**（动漫 / 漫画 / 轻小说）——它们的"状态"是进度的派生，
标了状态等于把「第 12 集」又说了一遍。**游戏不受此条约束**：通关度读不出来，只能用四档离散状态
（在玩 / 已通关 / 想玩 / 搁置）代替进度，且只出现在两处 —— 作品卡的副信息行、作品区的筛选按钮。
不做彩色角标、不做分组、不排序。**音乐也不受约束**，但它没有状态，只有发行形态（专辑 / 单曲 / OST / 广播剧）。

### 0.6 分区即介质，介质不重复标注

五个分区（动漫/游戏/漫画/轻小说/音乐）各自是一个"大区"，作品卡、列表行、作品区卡片都不再标介质；介质信息只出现在**跨介质的场合**（系列页、典藏、百科关联作品）。

### 0.7 每个分区的功能必须不同

动漫/游戏/漫画/轻小说差异巨大，功能键、详情页主体、阅读/播放形态都要**按介质分化**，不允许一套界面套五个分区。

**判据（2026-10-30 补）**：动手做一个"通用"控件之前，先问一句 **「这一类东西的『状态』是什么维度？」**
- 动漫 / 漫画 / 小说：有位置 → 进度（在看 / 已看完）；
- 游戏：没有位置 → 离散状态（在玩 / 已通关 / 想玩 / 搁置）；
- 音乐：连状态都没有 → 发行形态（专辑 / 单曲 / OST / 广播剧）。

落到这张表上的结论就是 **§2.5 的五套筛选**：排序项也不一样（只有游戏和音乐才有"年份"可排）。
**把一套控件套到五个分区上，就是把差异抹平 —— 属于返工项，不是"先做通用版以后再说"。**
这条同样适用于**任何"同类扩展"任务**（新增一个分区、新增一种榜单、新增一种列表）：先列这一类的特有属性，再决定控件。

### 0.8 原型阶段只要形状

快速迭代时只保证**结构与逻辑正确**，不追求像素级精细；颜色、动效可以粗，但信息架构、交互路径必须对。

### 0.9 动效必须整页一致，状态变化必须局部刷新

- 页面里**不允许"上半部分在动、下半部分直接出现"**——要么整页一起动，要么都不动（详情页上部因此取消了上浮动效）。
- 一次点击**只改变它该改变的那一处**：点"追番"只换按钮文案与状态，**不许整页重渲染**（整页重渲染会重播入场动画、丢失滚动位置）。
- 列表里切换分区/排序这类整体变化可以重渲染，但**单个按钮的状态切换一律局部更新**。
- **同一视图内的重绘（切筛选 / 切排序 / 选中）不重播入场动画，也不滚回页顶**：原型用 `.view[data-anim="same"]` 落地。
- **换页面必须播转场，而且不同导航动作要用不同动作**（v2.7）：底栏换 tab、首页换分区、进子页、退回来，这四件事观感必须能分辨出来。
  一律"淡入"等于没做——用户看不出自己是往前走了还是退回来了。规格见 **§4.6**。
- **转场只在最外层 `.view` 上播一次**，不许给每张卡片各配一条入场曲线：各配各的会连成一片乱动，
  整页看起来像在抖，而不是"翻过去一页"。
- **动画的作用域必须收缩到"真的变了的那一块"**（v2.8，这条优先于上一条）。
  判断方法：问一句"用户点了什么，屏幕上有几处变"。
  - **换分区**：变的只有内容（Hero / 功能区 / 分组），分区条只是换一个高亮 → 动画只给 `.page-body`，
    分区条留在它外面，**不许跟着横滑**（跟着滑就是"动了用户没点的地方"）。
  - **作品区切「我的追番 / 我的游戏」**：同理，tab 条不参与，只让内容淡入。
  - **「换一个」**：变的只有一个 Hero → 只替换 `.hero` 这一个元素，其他 DOM 一个都不重建。
    整页重渲染会让功能按钮、标签分组全部重播入场动画——用户点的是"换一张推荐"，不是"换了一页"。
  - **换页（进子页 / 退回 / 切底栏）**：整页都变，这时才把动画给 `.view`。

### 0.10 列表里的文字不能因操作而位移

排序/筛选控件切换选中态时，**文字位置必须固定**：箭头、图标之类只做透明度/旋转变化，且**始终占位**，不许插入后才布局。

**2026-10-30 扩到"布局"层**：不只是文字，**整块内容的位置也不许因为局部变化而移动**。
- 进入 / 退出管理态、展开 / 收起面板，只能改**那一行自己的内容**，不许新增一行把下面的东西推下去；
- 实测标准：进入管理前后，`.shelf-grid` / `.series-grid` 的 `getBoundingClientRect().top` **必须完全相等**
  （本轮实测：198 → 198、127 → 127）；
- 反例（本轮修掉）：作品区的操作条原先在管理态**另起一行**，一点下去整片卡片下移 30px，退出再弹回来；
- 一句话：**交互是在原地长出来的，不是把页面重新排一次。**

### 0.11 数据必须经得起看

原型里的每一条数据都会被当真看，所以**不许凑数**。

- **只收日本作品**：轻小说这个介质基本只有日本有，中文网文暂不做；欧美 IP（漫威等）一律不收。收进来的必须是该介质的真实作品，不能拿"同名的游戏"顶动画位。
- **介质要对**：`kind` 写 game 的就得真是游戏（黑神话悟空、Galgame 都算游戏），不能因为名字相关就塞进动漫分区。
- **来源要真实且分情况**：原作就是原作，改编才写"改编自 X"。见 §3.8 的 `og` 枚举。
- **系列多的作品优先**：数据要能压出"卷数很多""集数很多"这些边界（海贼王 113 卷、柯南 107 卷、JOJO 132 卷），否则测试不出卷列表、进度百分比、长列表滚动。
- **封面用真图**：从公开接口抓真封面存本地引用，**不许用纯色块/渐变顶替**——渐变只在真图缺失时兜底。
- **封面要抓就抓最大的**：AniList 有 `large`(230×345) 和 `extraLarge`(460×650)，只取 `extraLarge`；
  Steam 用 `library_600x900`。原图小于展示尺寸，再好的排版也救不回清晰度。
- **题材词表要统一**：同一分区里同类作品要落到同一个词上（轻小说的 `重生/网游/虚拟现实` 统一成 `异世界`），
  否则每个题材都只有 1–2 部，分组永远是空的。

### 0.12 地址写错要说出来，不许静默假装正常

- **未知视图 / 未知 id / 未知功能页 key，一律渲染 404 空态**（`404` 大字 + "这个页面不存在" + 说出找不到的是哪个地址 +
  「回到首页」「返回上一页」两个出口）。**禁止**静默回落到首页、也禁止渲染一个只有标题的空壳页——那等于把错误藏起来。
- **一个状态只有一个来源**：分区参数统一用 `p`（`#/aggregate?p=` `#/shelf?p=` `#/category?p=`）。
  历史别名 `sp` 只在 `route()` 里做兼容，**不许让两个参数各管一半**——之前 `#/shelf?p=game` 会静默显示动漫，就是这么来的。
- **空态要能走出去**：404 页必须带「回到首页」按钮，不能只留一段文字让用户自己改地址。

### 0.13 绝对定位的封面，必须被它自己的盒子裁住

`coverInner(w)` 吐出的 `.cover-img` 是 `position:absolute; inset:0; width/height:100%`。
只要**装着它的容器没写 `position:relative`**，这张图就会去找更上层的"包含块"——
带 `transform` 动画的卡片、带 `backdrop-filter` 的浮层都会临时成为包含块，
于是 44px 的封面被画成整屏大图，还把卡片标题压在下面（歌手页、歌手详情、迷你播放条都栽过）。

**新增任何"装封面的盒子"，第一件事是 `position:relative` + `overflow:hidden`。** 这条没有例外。

> 复发记录：歌手页/歌手详情/播放条（v2.6 修）→ 下载中心缩略图（v2.6 修）→ **资源管理页（v2.9 修，整页被 42px 封面盖死）**。
> 三次都是"新写一个容器，忘了抄那两行"。落代码时应把封面容器收敛成**一个**组件/类名（`.cover-box`），
> 而不是让每个页面各写一个 `.xx-cover`——容器越分散，这条铁律就越守不住。

### 0.14 不许给滚动容器常驻 `will-change`

`will-change` 是"我马上要动，先帮我提升"的临时声明，**不是性能开关**。
`.view` 是全站滚动容器，一旦常驻 `will-change:opacity,transform`，整页会被提升成独立合成层：
作品区 58 张封面的长列表白占显存，**而且动画结束后该层仍然存在**，某些渲染路径下会截到空白帧（本轮截图验证时整屏空白就是这么来的）。
`animation` 本身会临时提升，不需要手动声明。

## 1. 产品定位

- **形态**：个人自用、单机、本地运行的桌面软件（Windows 为主），**不公开分发**。
- **核心痛点**：在 B 站看番，大量番因版权缺失看不了，需自行去多个网站找资源。需要一个软件**统合**这些源——只需知道作品名，点进去就能自动爬取播放，不用挨个网站试。
- **使用场景**：以**补老番为主、有计划性**（看完动画去找原作小说/漫画续内容）；新番较少，一般仍走 B 站。
- **涉及 IP（示例）**：只取日本作品——Fate/型月（动漫+游戏+漫画+轻小说四介质）、命运石之门、Re:Zero、无职转生、物语、进击的巨人、电锯人、辉夜、芙莉莲；长系列用海贼王 / 名侦探柯南 / JOJO / 火影 / 龙珠 / 魔法禁书目录 压边界。欧美 IP（漫威等）与中文网文**不在范围内**。
- **灰色地带**：用户自用、接受灰色资源源站、不公开分发。
- **参照系**：
  - 源架构 → **Kazumi**（规则驱动，规则可导入/备份）
  - 界面 → **B 站**（番剧索引式分类页、新番时间表、排行榜 podium、双层导航）
  - 游戏分区 → **3DM**（新游推荐 / 即将发售 / 评测 / 攻略 / 排行榜）
  - 漫画阅读 → **Cimoc**；小说阅读 → **BiliNovel**（其缺点：设置少、字体少、不能缓存、加载慢、有广告——均需规避）
  - 老番痛点：同一番被拆在多个站、各缺几集（**集数拼图**是本软件核心价值）

## 2. 信息架构

### 2.1 顶栏（全局常驻，只允许三样东西）

```
[图标 A] ACGN   [⌕ 搜索作品 / 歌手 / 标签…  | 范围 全部 ⌄]   [下载中心 ⤓]
```

- **品牌位只写 `ACGN`**：加上分区名（"ACGN 聚合""ACGN 首页"）都会与底部导航的那一项打架——品牌是名字，不是入口。

- **只放**：软件图标 + 名称、展开式搜索框、下载中心快捷入口。
- **禁止**：主题切换按钮、设置按钮、缩小的搜索图标、任何其他入口。
- **搜索框必须长方形**：`border-radius: var(--r-md)`（10px，不是 pill 的 999px）、`min-height: 40px`、`padding: 0 var(--s-4)`、1px 边框。圆角只做"柔和的方"，不做胶囊。
- **光标必须看得见**：`input` 显式写 `caret-color: var(--sel)`，且 `height/line-height` 同值（38px），不能用 `padding` 顶高度导致插入符偏上或不可见。
- **图标与 placeholder 必须同一水平线**：图标容器 `display:flex; align-items:center; justify-content:center; line-height:0; flex-shrink:0`——**靠 flex 居中，不靠文字基线**，这是两者错位的唯一根因。

#### 2.1.1 搜索范围（2026-10-29 新增）

**范围是搜索框自己的状态，不是分区的状态。** 这是本节的唯一要点。

- **位置**：搜索框内部最右侧，左侧一条 1px 分隔线，`align-self:stretch` 与输入框等高。
  标签写「范围 + 当前值」（`范围 全部 ⌄`）；宽度 ≤620px 隐藏「范围」二字，≤440px 连箭头一起隐藏，只留当前值。
- **选项**：`全部` + 五个分区，每项右侧标数量（`19 部`），选中项打勾 + 底色。菜单是绝对定位浮层（`.search` 上写 `position:relative`，不要让它去认 `.topbar`），点空白 / Esc 收起。
- **占位文字跟着走**：范围不是「全部」时写 `在音乐里搜索…`，否则用户会以为还在全站搜。
- **不许回写 `state.partition`**：范围一旦改了分区，用户清空搜索词之后会莫名落到另一个分区的首页。
  搜索态下点分区条＝把范围收到该分区（两处控件指向同一个状态），但那是用户主动点了分区，不是范围在背后改分区。

**结果页三种形态**

| 范围 | 标题 | 分组 | 分区条 |
| --- | --- | --- | --- |
| 全部 | `搜索「fate」` + `全部范围 · 5 个分区 · 5 项` | 按分区成组，组标题右侧带条数，顺序固定（动漫→游戏→漫画→轻小说→音乐） | **一个都不高亮**（结果不属于单一分区，高亮任何一个都是误导） |
| 单分区 | `音乐 · 搜索「LiSA」` + `范围：音乐 · 1 项` | 平铺 | 高亮该分区 |
| 单分区且别处有结果 | 同上 | 平铺 + 底部一条「其他分区还有 N 项 · 在全部范围中查看」 | 高亮该分区 |

- **空结果必须给出口**：全部范围提示换关键词；单分区且有别处结果时，直接给「在全部范围中搜索」按钮。
- **为什么要有这个控件**：旧实现把范围绑死在 `state.partition` 上——想搜「Fate」得先切动漫搜一次、再切游戏搜一次。跨介质作品正是本软件的立身之本，搜索却是单分区的，等于把长处藏起来。

### 2.2 底部导航（常驻四项）

`首页 / 作品区 / 典藏 / 我的`

- **"聚合"已改名为"首页"**：用户点它要的是"回到出发点"，而"聚合"描述的是实现机制（把多源聚合起来），不是去处。
  牵一发动全身的地方都要跟着改——导航项、返回文案（`返回首页 · 动漫`）、404 出口（`回到首页`）、设置里的启动页选项。
- "书架"这一名称已废弃 → 统一叫**作品区**（因为里面同时装动漫/游戏/漫画/小说/音乐）。
- 详情/分类/功能页高亮归"首页"；下载/资源管理/设置/各功能面板高亮归"我的"。

### 2.3 首页结构（原「聚合」，自上而下）

1. **分区条（五个并列，等宽铺满一行）**：`动漫 / 游戏 / 漫画 / 轻小说 / 音乐`，**保持原有形态，不做成下拉按钮、不做成单个「全部」按钮**。点哪个就切到哪个介质，默认动漫。
   - **音乐是 2026-10-29 新增的第五个分区**：只收二次元向音乐（动画主题曲、OST、同人专辑、Vocaloid、广播剧），
     与四个"作品"分区并列，共用同一套 Hero / 功能区 / 题材分组三段结构。
   - **不设"全部=跨介质混排"这个范围**：跨介质浏览是「搜索」和「典藏」的事，首页按介质分区。
   - 搜索**只在当前分区内进行**，标题写明分区（如"游戏 · 搜索「XXX」"）；切分区时保留搜索词，在新分区内重新搜。
2. **随机推荐（Hero）**：从**当前分区内**随机抽一部（动漫只推动漫、游戏只推游戏），带评分/年份/题材标签/简介，操作随介质变化：
   - 动漫 → 立即播放；游戏 → 启动游戏；漫画/小说 → **开始阅读**；音乐 → **播放全部**（连播整张专辑）；均附"换一个"。
   - **封面就是这个背景框本身，且贴在右边**，结构固定三层——
     `hero-bg`（同一张封面放大、`blur(24px)`、`brightness(.48)`，负责把整块填满）→
     `hero-poster`（**同一张封面裁切占右侧 46%**，此处是缩小而非放大，所以清楚；**左缘**用 `mask-image` 渐隐，融进打底）→
     `hero-veil`（左实右透的横向压暗 + 底部第二层，保证左侧文字可读）。
   - **为什么封面必须在右、信息必须在左**：整块左侧（含大标题、简介、按钮）都归信息，文字区因此有近 2/3 屏宽；
     封面在左时信息只剩右边一条窄栏，长简介放不下、按钮要折行。**左边是"渐变"，右边是"图"**，这是这个模块的构图铁律。
   - **文字全部在左侧信息区**：`hero-inner` 宽度上限 `min(720px, 66%)`。
   - **竖向必须三段（`hero-head` / `hero-body` / `hero-actions`）**，不许从上往下依次挤：

     | 段 | 内容 | 弹性 |
     | --- | --- | --- |
     | `hero-head`（置顶） | `随机推荐` 小标 → `<h1 class="hero-title">`（`clamp(26px,3.2vw,40px)`，两行截断）→ 评分/年份/题材/曲目数 chip → **简介（全文，不截断）** | `flex:0 0 auto` |
     | `hero-body`（纯留白） | 空的弹簧，负责把按钮顶到底 | `flex:1 1 auto` + `min-height` |
     | `hero-actions`（贴底） | 主按钮 + 换一个 | `flex:0 0 auto` |

   - **简介必须紧跟评分，不许居中悬挂**（v2.7 修正）：简介回答的是"这一部讲什么"，是标题的下一句，
     用户的视线从标题下来第一眼就该读到它。上一版把简介丢进 `hero-body` 居中，等于在标题和简介之间硬塞一块空气，
     眼睛要走完一段空白才接得上话。现在 `hero-body` 退成空弹簧，空白统一落在**简介与按钮之间**——
     那段空白是"留给简介的额度"，简介短就空着，简介长就吃掉它，按钮位置始终不动。
   - **简介不做行数截断**：数据里最长的简介 75 字、平均 47 字，在 720px 宽、15px 字号下最多两行，
     为了"排版整齐"砍成一句话，等于把用户最想看的剧情说明藏起来。字号 `--t-md`（15px）、行高 1.78。
   - **为什么必须分段**：一段流式布局里，"标题多长""简介几行"会直接决定按钮落在哪里，五个分区五张 Hero 的按钮高度全不一样；
     分段后**标题永远在上、按钮永远在下**，长名短名、长简介短简介都不改变按钮位置。
   - **标题用 `<h1>`**：Hero 是页面主视觉，整页必须有且只有一个 h1，之前把名字塞进封面小字里导致页面没有标题层级。
   - **meta 里不写介质**：分区条已经决定了介质，chip 里再来一个「动漫 / 游戏」是同一句话说两遍；
     Hero 标题也去掉「（漫画）/（小说）」这种同名区分后缀。
   - **整块 `.hero` 就是详情页入口**：`data-action="open-detail"` + `role="link"` + `tabindex="0"`（Enter/Space 可触发），主按钮之外的空白、封面、简介都可点。**不允许出现"只有按钮能点、封面点不动"**。
   - **右上角续播按钮（`hero-resume`）只属于这一张推荐**（2026-10-30 修正，两条都是从错例改回来的）：
     - **介质必须与当前分区一致**：只在 `w.kind === state.partition` 的作品里找"未看完"，找不到就**不显示**，
       **绝不往全站回落**。错例：游戏分区的随机推荐上飘着一颗「继续观看《命运石之门》第 12 集」——
       按钮说的和整页说的不是同一件事，点下去还会跳去别的介质，比不显示更糟。
     - 文案按介质分：动漫 `继续观看 · 第 N 集`，漫画/小说 `继续阅读 · 第 N 卷`；**游戏与音乐没有续播进度，不出现**。
     - **点「换一个」＝同时撤掉它**：用户换掉的正是"不想接着这个往下看"，把续播按钮留在新换的推荐上，
       等于把刚被否掉的选项又推回来一次。隐藏只对**这一次首页访问**有效——切分区、或离开首页再回来即恢复。
   - 移动端（≤620px）：`min-height:340px`，封面通铺整块、改为上下方向渐隐（只在顶部保留清晰区），文字压在图下半部分，标题降到 `--t-xl`。

3. **功能区**（分区专属，**等宽 grid 排满一整行**，不留空位、不允许出现与别人不同款的按钮）：
   | 分区  | 功能键                                |
   | --- | ---------------------------------- |
   | 动漫  | **全部** · 时间表 · 排行榜 · 标签广场           |
   | 游戏  | **全部** · 新游推荐 · 即将发售 · 排行榜 · 评测 · 攻略 |
   | 漫画  | **全部** · 排行榜 · 最近更新 · 标签广场          |
   | 轻小说 | **全部** · 排行榜 · 更新表 · 标签广场            |
   | 音乐  | **全部** · 每日推荐 · 排行榜 · 歌手 · 分类歌单 · 广播剧 |
   - **第一个按钮固定叫「全部」**（不是"分类"）：进入本分区的全量作品列表 + 筛选页。名字就叫"全部"，因为它就是"这个介质的全部作品"；叫"分类"会让人以为进去是分类导航。
   - 不设"我的追番/我的收藏/我的书架"按钮 —— 这些都是下方作品区的事。
   - **音乐这 6 个按钮是对着主流音乐平台抄的结构**（网易云「发现音乐」：个性推荐 / 歌单 / 排行榜；QQ 音乐「音乐馆」：歌手 / 排行 / 分类歌单 / 电台）：
     `每日推荐` 对应"每日歌曲推荐"，`歌手` 对应"歌手分类"，`分类歌单` 对应"歌单广场"，`广播剧` 是二次元场景特有的分类。
     **抄的是信息结构，不是抄皮肤**——按钮形态仍然是本软件的一套等宽按钮。
4. **题材分组区**：统计当前分区高频题材，取 4 组，每组 **6 部**作品（一行 6 列）：
   - 组标题 = 题材名（**不带 `#`**），**标题本身可点 → 跳分类页并带上该题材**；
   - 右侧只有一个**圆形图标按钮**（刷新/换一批），不写文字、不设"更多"按钮；
   - 卡片信息 = 封面 + 名称 + 年份/评分（**不重复该组题材**），名称与年份各一行、`nowrap` 截断。
   - **为什么是 6 部而不是 3 部**：三列时封面要撑到 300px 以上，而抓来的封面原图只有 460px 宽，
     等于每张都在放大，看久了发糊；六列约 150px，反而接近原图尺寸，**显示更多 = 更清楚**。
   - **网格必须写 `repeat(6, minmax(0,1fr))`**：默认 `1fr` 的下限是 `min-content`，
     一个长标题（`Fate/stay night [Heaven's Feel]`）就把那一列撑宽，整行六列立刻不等宽；
     `.tag-work` / `.tw-name` / `.tw-meta` 同时补 `min-width:0`。
   - 题材门槛：该题材至少 **3 部**作品才成组（不足会出现空卡片位）；确实凑不满 4 组时**宁可少几组也不凑数**。
5. **四个作品分区都要有分组**：游戏区曾经因为"每个题材都不到 3 部"整片空白——
   解决办法**不是**降低门槛，而是把游戏数据补足到 14 部、让题材真正重叠（剧情 / JRPG / 动作 / 悬疑 / 催泪）。
   **数据不够就补数据，不许让页面空着。**

### 2.3.1 音乐分区（二次元音乐 · 2026-10-29 新增）

音乐不是"第五种作品"，它是**有曲目、有时长、能连播**的另一种东西，所以下面这几条与四个作品分区不同：

**① 封面一律方形。** 音乐封面是 CD 方图，塞进竖版海报的比例会被拉长。
实现上**不逐个容器改**，而是在 `[data-kind="music"]` 下把所有装封面的盒子（`.cover` / `.wi-cover` / `.rel-cover` / `.rank-cover` / `.detail-cover` / `.al-cover` / `.mp-cover` …）统一 `aspect-ratio:1/1`，字段一处、全站生效。

**② 没有进度。** 和游戏一样，音乐不记"看到哪"，`deriveProgress()` 直接返回 `null`。
作品区两行改成：第一行 = 发行形态（`单曲专辑 / 专辑 / OST / 同人专辑 / 广播剧`），第二行 = `N 首 · 总时长`（`albumDur()`，超过 1 小时写「1 小时 12 分」）。

**③ 五个功能页的规格**

| 页 | 做法 | 关键约束 |
| --- | --- | --- |
| 每日推荐 | 用**日期做种子**打乱后取 12 张 | 同一天进来永远同一批（像真有编辑在排），换天自动变；12 张 = 六列两行正好铺满 |
| 歌手 | 按 `artist` 聚合，圆形头像用首张专辑封面 | 副标题写**曲目数**（"1 张"看不出内容量）；歌手页补「热门歌曲」曲目表，否则单专辑歌手页就是一个头像 + 一屏空白 |
| 分类歌单 | 按题材聚成歌单，封面用拼贴 | 拼法随张数变：4 → 2×2、3 → 左一竖 + 右两横、2 → 并排、1 → 单图。**绝不拿别的专辑凑满 4 格**（广播剧歌单里混进一张流行单曲等于说错话），也绝不重复同一张 |
| 广播剧 | 就是 `albumType==='广播剧'` 的专辑网格 | 不做成第六个分区：它仍是"一张碟" |
| 排行榜 | 与四个作品分区同一套组件 | 热度口径换成「播放量」 |

**④ 专辑详情页 = 曲目表。** 封面 + 标题 + chip（评分/年份/`N 首 · 总时长`）+ 简介 + 主按钮「播放全部 · N 首」，
下面是曲目表：`序号 / 曲名 / 时长` 三列，**整行可点即播放该曲**，正在播的那行整行高亮（`.track-row.on`）。

**⑤ 迷你播放条（`#miniplayer`）**：点「播放全部」或任一曲目后，从底部滑出，**贴在底部导航上方**（`bottom: var(--bottom-h)`）。

- 内容：44px 方封面 → 曲名 → `歌手 · 第 n/N 首` → 3px 进度条 → `0:03 / 4:09` → 暂停/下一首/关闭；
- 一秒推进一次，**一首放完自动下一首**，整张放完停在最后一首（不循环、不静默跳专辑）；
- 出现时给 `body` 加 `mp-on`，把页面底部内边距顶开 78px，**不许盖住正文最后一行**；
- 离开页面不销毁：播放状态在 `state.mp` 里，切页面后播放条继续在。

**⑥ 分类页的音乐维度**：形态（单曲专辑/专辑/OST/同人专辑/广播剧）、曲风、年份；排序是「播放量 / 评分 / 发行时间」——**不设"更新时间"**，音乐没有连载更新。

**⑦ `og`（来源）字段留空**：OST 依附动画、同人音乐本身就是原作，任何"改编自 X"的写法都会写错。空值的作品不参与来源筛选。

### 2.4 分类页（"全部作品"的唯一入口）

- 顶部：`返回X首页` + 标题 **"动漫 · 全部"**（入口叫什么，页面就叫什么）+ 「筛选」开合按钮；**标题右侧不写"共 N 部"**（计数属于无效信息）。
- **排序 tab**：热度 / 评分 / 更新时间 / 年份，再点一次切升降序。
  - **不设"更新"这一项的游戏分区**；年份一间按介质命名（动漫=开播时间、漫画/轻小说=开始连载、游戏=发售时间、全部=发布时间）。
  - **箭头常驻占位、只变透明度**，切换排序时文字不许左移或跳动。
- **筛选面板**（点"筛选"展开）：
  - **不设「介质」这一维**：进这个页就已经在某个介质里了，再筛介质是重复功能（选别的介质 = 换分区）；
  - **类别**（连载 / 完结 / 新番 / 剧场版）只在筛选面板里选，**页面上不再单列一行**（那是同一概念的两处入口）；
  - 题材 / 年份 / 季度（游戏无）/ 改编来源（游戏无），**每一行首项都是"全部"**；同维度多选为"或"，跨维度为"与"。
- 已选条件以可删除 chip 呈现，右侧"清除全部"。
- 结果区为**海报网格**：左上评分角标；**不出现本地资源角标**（"已下载"只在详情页标注，别处出现即为信息重复）。
- **卡片标题统一单行省略**（超长打省略号），保证下面的集数/标签始终对齐。
- 空态必须给"清除全部条件"。

### 2.5 作品区（原书架）

- **没有页面标题**：分区切换条本身就是标题，五个按钮固定为
  **`我的追番 / 我的游戏 / 我的追漫 / 轻小说书架 / 我的音乐`**（不再另起一行写"作品区 · 我的追番"）。
- **管理只有一个入口：工具条右侧的「管理」按钮**（2026-10-30 修订，原「桌面右键 / 移动端长按 450ms」**作废**）。
  - 同一功能给三条路径，用户还得先发现其中一条 —— 显式按钮出现后，**手势入口一律删除**，不留"老用户还记得"的兼容分支。
  - 进入管理：工具条**原地换内容**为 `已选 N 项 · 移出作品区 · 完成`；点卡 = 多选；封面右上角圆形选择标记；选中卡描边用该作品的 accent 色。
  - 「完成」退出；切换分区也退出。
- **工具条只占一行，装三样**：排序下拉 + 筛选 chips（**可横滑**）+ 右侧「管理」。
  **管理态与常态共用这一行**（换内容不换高度），理由见 §0.10 —— 管理条原先另起一行，一点下去整片卡片下移 30px、退出再弹回，像页面在跳。
  - **chips 横滑**（2026-10-30 定）：5 个筛选项 + 排序 + 管理在 390 宽下装不进一行，硬换行会让「已看完 / 管理」掉到第二行、看起来像一组；
    现在 chips 区 `overflow-x:auto`、排序与「管理」固定不动。**右侧渐隐只在真的滑得动时出现**（按 `scrollWidth > clientWidth` 加类），
    否则刚好放得下的最后一个 chip 也会被虚化，像被截断。
  - **工具条不再写「共 N 部」**：这一行装不下四样东西。数量由网格本身和空状态表达，筛选后的条数由「这个筛选条件下没有作品」兜底。
  - 排序下拉只显示**当前值**（`最近观看 ⌄`）+ 前置的滑杆图标，不再写「排序」两个字 —— 省下的 30px 让动画分区也能三个 chip 全露出来。
- **排序与筛选按介质各配一套**（§0.7「每个分区功能必须不同」在本页的具体化）：

  | 分区 | 排序 | 筛选 chips |
  | --- | --- | --- |
  | 我的追番 | 最近观看 / 名称 / 评分 | 全部 / 有更新 / 在看 / 已看完 |
  | 我的追漫 | 最近阅读 / 名称 / 评分 | 全部 / 有更新 / 在读 / 已读完 |
  | 轻小说书架 | 最近阅读 / 名称 / 评分 | 全部 / 有更新 / 在读 / 已读完 |
  | 我的游戏 | 最近打开 / 名称 / 评分 / 发售年份 | 全部 / 在玩 / 已通关 / 待玩 |
  | 我的音乐 | 最近播放 / 名称 / 评分 / 发行年份 | 全部 / OST / 专辑 / 单曲 / 广播剧 |

  - **判断方法（以后新增一个分区，必须先回答）**：这类东西的「状态」是什么维度？
    - 有可读位置的（动漫 / 漫画 / 小说）→ 用**进度**：在看 / 已看完；
    - 没有位置的（游戏）→ 用**离散状态**：在玩 / 已通关 / 想玩 / 搁置。通关度**读不出来**，硬算一个 62% 就是编的；
    - 连状态都没有的（音乐）→ 只能按**发行形态**：专辑 / 单曲 / OST / 广播剧。
  - **筛选项必须能在卡片上被看见**：游戏卡副信息行写 `在玩 · 26.4 GB`。筛完还是一片一模一样的卡，等于没筛。
  - **切分区时筛选复位**：在「在看」里点到游戏分区，那个筛选项在新分区里根本不存在。
- 卡片：封面 + 名称 + **两行进度信息**。
  - **点封面 / 点名称 ＝ 接着看，不是进详情**（2026-10-30 定）：番=播放器（续到上次那一集）、漫画/小说=阅读器、游戏=启动、音乐=播放这张专辑。
    这一页的全部意义是「接着看」，中间再插一页详情就是多一道墙。
  - **详情从两处进**：封面右上「⋯ → 作品详情」；或从播放页 / 阅读器退出时**落在详情页**（那里就是它的"上一级"）。
  - 封面右上「⋯」**只放这一部作品的动作**：作品详情 / 百科 / 下载到本地 / 移出作品区（移出必弹确认框）。
    - **不放「继续观看」**：封面本身就是继续，同一个动作给两个入口是重复。
    - **不放「管理作品区」**：整页的管理属于整页，工具条右侧已经有「管理」；从单张卡的菜单里进批量管理，语义上说不通。
  - 封面右下 **`继续观看 / 继续阅读 / 启动`**（文案按介质，音乐的卡没有这一颗 —— 一张专辑没有"继续"可言）；
    触屏（`hover:none`）不显示这颗 —— 点封面已经是同一个动作。
  - **「更新」角标在封面左上**，右上永远留给「⋯」：两者都放右上时角标 z-index 更高，会把「⋯」整个盖住，点了像没反应。
- **作品区标题不带"（漫画）/（小说）"后缀**：这个区已经按介质分好了（「我的追漫」里不可能出现轻小说），
  名字里再标一次介质就是同一句话说两遍。后缀**只保留在分类页**这种混合列表里（跨介质同名时才加，见 §3 第 9 条）。
- **进度信息固定两行**（第一行总量 / 第二行位置 + 百分比）：

  | 介质  | 第一行（总量）      | 第二行（位置 · 百分比）        |
  | --- | ------------- | --------------------- |
  | 动漫  | `全 24 集`      | `第 5 集` · `21%`      |
  | 漫画  | `全 34 卷`      | `第 12 卷` · `48%`     |
  | 轻小说 | `全 18 卷`      | `第 6 卷 · 第 3 章` · `18%` |
  | 游戏  | `PS5`（平台首项）   | `在玩 · 48 GB`（**无百分比**） |
  | 音乐  | 发行形态 `OST`    | `12 首 · 36 分钟`（**无百分比**） |

  - 第一行用次要色 `--sub`、字号 `--t-xs`；第二行的位置词用主文字色，百分比用 `--sub` + `tabular-nums`（数字等宽，上下行对齐）。
  - 「已看完」时第二行写 `已看完`，**不再挂 100%** —— `done` 本身已经是 100%，两句话说同一件事，只让这一行多占一格。
  - 位置词与百分比之间用 `--s-2` 间距隔开；两行都 `white-space:nowrap` + 省略号：只截断、不换行，保证网格行高一致。

### 2.6 典藏（系列整合区）

- **没有页面标题**（底部导航已写明"典藏"）；
- **不做分类、不显示进度、不显示是否在追/是否看完**；**不显示"收录 N 部 / 跨介质整合"这类计数文案**；
- 系列卡 = **竖版海报卡 2:3**：`sc-banner` 用海报原图、**不做横向裁切**（横切会把竖版海报的头部切掉），下方只留系列名 + `SINCE 起年份` + 介质 pills；右上角最多一枚角标（`N 部` 或 `自建`），不叠徽记；
- 点击 → 系列页。
- **2026-10-30 修订：典藏必须可管理**（原"不承担任何管理职责"作废）
  - 工具栏常驻两个按钮：**管理 / 新建典藏**；
  - 管理态：每张卡左上出现勾选框 → 底部浮出操作条（**移除 / 取消**）；移除只解绑系列，不删任何作品数据，并写 localStorage 记住隐藏项；
  - 新建典藏 = 自建系列：起名 + 从现有作品里勾选成员（`col-pick` 勾选面板），存 localStorage；
  - **封面允许用户自定义上传，入口在「管理」里**：管理态下勾中**恰好 1 个**系列 → 工具条「更换封面」亮起 → 选图后 canvas 压到 400×600 存 dataURL（避免原图几 MB 塞进 localStorage）。勾 0 个或 2 个以上时按钮置灰，并说明"选 1 个才能换封面"。
    卡片上不再常挂上传按钮：一页 20 张卡各挂一颗，等于把"管理"这个动作拆成 20 个按钮。系列封面"自动去网上找一张海报大图"列为待做（§9）。
- 计数只出现在**工具栏右侧一行小字**（`N 个系列 · 其中 M 个自建`），不进卡片、不做标题。

### 2.7 系列页（内容地图）

- `返回典藏`；头部：封面 + 系列名 + 介质 chips + 系列进度（已看 X/Y 部 · 当前《…》）；
- 排序：按介质分组 / 按故事时间线 / 按出版日期（**必须真的排序**，不许是假控件）；
- 行：封面 + 介质图标 + 作品名（最早一部标"建议从这里开始"）+ 进度/年份 + 评分。
- **2026-10-30 补**：
  - 必须有**系列简介**（`SERIES_META.intro`）与**「怎么看这个系列」的顺序说明**（`SERIES_META.order`）；
  - **故事顺序无法自动推导**（跨媒介的先后是设定问题，不是年份问题），所以顺序字段是**人工维护**的常量表，页面上要注明这一点，不要假装是算出来的；
  - 主操作：「从第一部开始」；次操作：「换封面」（同典藏的自定义上传）。

### 2.8 作品详情页（按介质分化，三明治）

**共用上部 = 三段式**（2026-10-30 改，与首页 Hero 同构）：封面在左，右侧竖排三块
1. **上 = 标题 + meta**：**评分只显示一个数 + 样本数**（`9.3` + `1.4 万人评分`，tooltip 标来源）/ 年份 / 介质 / 题材 chips / 来源 chip（`originText(w)`）/ 已缓存本地；
   - **只有媒体分，没有「我的评分」**（2026-10-30 撤除）：评分机制尚未定案，§10 是备选方案、未采用，
     详情页不预留打分入口。**不许**在详情页出现星级、`我的评分`、`我还想打几分` 之类的东西。
2. **中 = 简介**（`flex:1`，吃掉封面高度带来的留白 —— 这段话是这一区的填充物，不是附属说明）；
3. **下 = 操作按钮**（主操作、加入作品区、**下载**、百科）。**窄屏排成 2 行：主操作独占一行，其余三个各占 1/3**
   （2026-10-30 定）。四个按钮挤一行时「百科」会被挤到第二行独自靠左，看着像漏了一个；
   既不降级成文字链、也不减项，只改分配 —— 主操作仍然是这一块最显眼的。
- **进度条已删除**（原「第 12 集 / 共 25 集 + 62%」）：剧集格里已经标了当前集，两处说的是同一件事。
  **同一信息在一屏里只出现一次**，第二条一定是多余的那条。
- **百分比不进主按钮**：按钮文字只回答"去哪"（`继续阅读 · 第 108 卷 · 第 1 话`）。

- 按钮行**固定四个**，不许多到换行；「系列」是二级动作为它单独安排位置（见下方"相关作品"条）。

**主操作文案 = 真实行为**（不许出现"从最新进度播放"这种含糊说法）：

| 情况 | 动漫 | 漫画 / 轻小说 | 游戏 |
| --- | --- | --- | --- |
| 有观看/阅读记录 | `继续观看 · 第 5 集` | `继续阅读 · 第 6 卷第 8 章` | `启动游戏` |
| 完全没看过 | `从第 1 集开始` | `从第 1 卷开始` | `启动游戏` |

- 关闭播放器/阅读器后，**详情页这颗主按钮要跟着变**（局部更新文案，不整页重绘）。

- **不显示"状态/进度条"**：没看过的作品写"尚未开始"毫无意义——用户只需要知道"这是个新作品"，加入状态由"✓ 已在作品区"按钮自行表达。
- **上区不做上浮动效**：整页同进同出，避免"上半页在动、下半页直接出现"的割裂感。
- **点"追番/加入"只局部换按钮文案**，不重渲染整页（否则入场动画重播、上区闪一下）。
- **下载入口在这里**（按介质生成任务名），下载中心只负责展示队列；同一作品只允许一条任务，按钮本身回显"下载中 N% / 已下载"。
  - 按钮**没有"死状态"**：已有任务时点它 = 跳到下载中心去操作，不是弹个 toast 了事。

**主体按介质分化**（这是四个分区最大的差异点）：

| 介质  | 主体内容                                                               |
| --- | ------------------------------------------------------------------ |
| 动漫  | **剧集小格子平铺**（不横向滑动）；标题行右侧显示"共 N 集"，**不写"某年放送"**；格子内**只显示集数**，不显示源数量；**只高亮当前这一集**，不做「已看」标记、不做本地/在线配色、不做图例（缓存以一季为单位，集内分本地/在线没有意义） |
| 游戏  | 游戏信息卡：平台 / 发售 / 语言 / DLC·版本 / 成就。**不写游玩时长、最近游玩、存档**（这些是"进度"，与"游戏不记进度"自相矛盾）；主操作为"启动游戏"（**只出现一次**） |
| 漫画  | **卷 → 话**：每卷是可展开栏，卷封面 + 卷名 + 卷内话数，展开后列出各话                          |
| 轻小说 | **卷 → 章**：同上，单位为"章"                                                |

**共用下部**：相关作品**直接展开为封面卡网格**（同系列其他介质，**必须排除自身**；解析不到就不显示该块）。
- **网格里所有封面框同高（2:3）**：音乐的角色是"一张唱片"，不是"一张 1:1 专辑封面"——框拉成 2:3，封面缩成**居中的圆形唱片**，框底色是唱片纹（同心圆细线）。
  这样同一行的漫画/小说/音乐高度齐平；原先把音乐的框压成 1:1，整行出现高低差，网格看着像散了架（R11）。
- 卡片标题**允许两行**（`TVアニメ「進撃の巨人」Season 2 オリジナルサウンドトラック` 这种名字一行放不下），
  但**网格行高按"最高标题"对齐**，不许一张卡因为标题长就往下长一截。

- 「系列主页」是**二级入口**，做成"相关作品"标题右侧的文字链接（`系列主页 ›`），不占主操作行。

- **禁止**：制作信息、声优阵容、完整度提示（这些属于百科）；源数量/源名称（属于播放器）。

### 2.9 百科（站内页）

- 入口：详情页「百科」按钮；父级 = 作品详情（返回文案"返回详情"）；
- 内容：简介 / 基本信息 / 角色·声优（漫画小说无 CV）/ 制作信息 / 关联作品（可跳转）/ 资料源外链；
- 右上"重新刮削"必须有**三态**：可点 → 刮削中（禁用）→ 已更新；不能只有一个 toast 占位；
- **当前为"直接读取内置数据"的站内实现**，不是跳第三方；正式版接入刮削源（见 §5.6）。

### 2.10 我的 / 资源管理 / 设置 / 下载中心

**我的**

- **没有页面标题**（底部导航已写着「我的」）。头像是唯一的大元素 + 一行 `我 · 本地单机`；
  **头像右侧不写任何东西**（不写版本号、不写"全部数据只存在这台设备"式的说明——用户点进来不是来读说明书的，见 §0.4）；自定义头像上传列为待做，见 §9；
- **一屏到底的入口网格，不再分「常用 / 偏好」**：下载中心 / 资源管理 / 磁盘管理 / 浏览历史 / 观看统计 / 作品关系 / 源管理 / 引擎管理 / 同步备份 / 命名规则 / 通知 / 设置（12 格，四列三行，形状一致）；
- **取消「关于」分区**：页面最底一行只留 `ACGN v0.9` + 「检查更新」按钮，**不写软件定位、不写"原型演示版，数据不持久"这类自述**，不占格子；
  演示性质由各页面自己的一句 `demo-note` 说明，不需要在"我的"里集中声明；
- 排序原则：**按"用户来这一页的频率"排**，而不是按功能归属猜主次 —— 设置是终点，放最后不影响可达性。
- **禁止**：最近使用（与浏览历史重复）、追番/游戏/漫画/小说数量统计（观看统计里已有）、存储占用块（磁盘管理里已有）。

**资源管理**（2026-10-30 改版：列表 → 文件管理器）
- **本质是维护文件夹，不是维护一张清单**：资源以「可识别的固定格式文件夹」为单位（U 盘 / 本地 / NAS 均可，通过「初始化」识别），所以用文件管理器的形态，而不是把 78 部作品平铺成一张表；
- 三级结构：`根（五个分类文件夹） → 分类（作品文件夹） → 作品（具体文件，按集/卷拆开）`；
- 顶部面包屑可回上级（根层级显示为当前路径文字，不是按钮）；**搜索只作用于当前层级**；排序为名称/大小/类型，箭头常驻只切方向；
- 行内信息：名称 + 副标题（作品数 / 文件数·介质·年份）+ 最近更新 + 体积；作品行有「打开所在文件夹」「删除」两个动作，**删除一律先弹确认框**；
- 根层级补两样：**一条读数**（识别到 N 个分类 / M 个作品文件夹 / 合计 X GB —— 只是文字，容量图形归磁盘管理，不在此页放汇总内存条）与**「未识别文件夹」出口**（列出没被命名规则命中的文件夹，可「指定归属 / 忽略」，忽略只隐藏不删文件）；
- **并承担「资源目录」与「刮削缓存」两项设置**（改目录、清缓存本来就属于资源管理，不该放在设置里）。

**磁盘管理**（新页，入口在我的 → 磁盘管理；资源管理页头也有一个跳转按钮）
- 一块盘一张卡：盘名 + 类型（内置 SSD / 内置 HDD / 可移动 / 网络位置）+ 总容量 + 可用容量；
- 一条分段条表达三件事：**灰 = 盘上其它文件，彩色 = 软件识别到的各分区资源（动漫/游戏/漫画/轻小说/音乐五色），白 = 空闲**；图例带具体 GB；
- 页尾两行说明：读数是演示数据、正式版读真实容量；识别依据是文件夹结构（见资源管理的初始化）；
- **不放"清理/压缩/格式化"这类会动用户盘的按钮**，这里只做"看见"，动手去文件管理器。

**设置**（2026-10-30 改版）
- **取消「偏好 / 常用」的区别，所有设置项排在一页**，按主题 / 通用 / 播放 / 弹幕 / 通知 / 存储 / 高级分六组，组内是同类项；
- **取值项一律用下拉（`<select>`），不再用"点一下循环下一个"的文字行** —— 后者看不出能点，也不知道还有几个选项；
- 主题（跟随系统 / 浅色 / 深色 / 按时间自动 19:00–07:00）**只能在这里改**；**不放资源目录与缓存清理**（在资源管理）；
- 页尾一行版本信息，不另设「关于」。

**下载中心**：只管**传输任务**，不管磁盘内容（磁盘归资源管理，一条内容不许两边都列）。
- 顶栏下载图标**常驻所有页面**，是"快速进下载中心"的入口，不需要先回"我的"再点；
- 汇总条（下载中数量 / 总进度 / 剩余时间 / 全部暂停·全部继续 / 清空已完成）+ 筛选（全部 / 下载中 / 已暂停 / 完成 / 失败）；
- 队列行：进度、速度或剩余 + **一个主操作**（暂停 / 继续 / 打开 / 重试）+ **「⋯」**（打开文件 / 换源重下 / 打开所在文件夹 / 删除）。
  - **一行的动作不超过一个按钮 + 一个「⋯」**（2026-10-30 定）：三个按钮并排会吃掉 150px，作品名被压成「物语系…」；三行高度还会变成 100/105/155。
  - **失败原因只占一行**（`连接源超时，可换源重试`），完整原因放 `title`：原来那句带括号的长文案把行撑到 155px。

### 2.11 播放器（覆盖层）

- **播放器独立于主站**：全屏覆盖、恒暗、线性图标（不用主站的填充图标），视觉上要让人知道"这是播放器，不是详情页的一部分"；参考 B 站播放器而非 Netflix 大标题风格；
- 顶部（关闭 / 标题）+ 控制栏；**集数选择器收进「选集」按钮**，点开从下往上弹出竖列表（当前集高亮、已缓存集标"本地"），不再占一条常驻缩略条；
- 控制栏 **恒定两行**（2026-10-30 重做）：上行 `当前时间 · 进度条 · 总时长`，下行按钮组。
  - **时间贴进度条两端**而不是写成 `00:12 / 24:10`：一条 `min-width:88px` 的时间会把进度条挤掉四分之一。
  - **窄屏只留 `上一集 / 播放 / 下一集 / 选集 / ⋯ / 全屏`**；清晰度、字幕、片源、倍速、音量收进「⋯」的播放设置面板。
    全塞进第二行会折成 4 行，`⛶` 还会被挤到单独一行靠左。
  - 宽屏（≥720px）反过来：那一排全部就地展开，「⋯」隐藏。两套入口、同一组动作，不许只有其中一套能用。
  - 面板里是**一次点选**（选中态高亮），不是「点一下换下一个」。
- **键盘快捷键**：`空格` 播放暂停 · `← →` 跳转 · `↑ ↓` 音量 · `N` 下一集 · `Esc` 退出；控制栏末尾给一行浅色提示（窄屏隐藏）；
- **进度条点击 = 按点击位置 seek**（不是固定 +10% 的假交互）；
- **该集所有可用源只在播放器内呈现**，源失败自动回落；续播时提示"已从上次位置继续"。
- **未播放时不是黑屏**：虚化的封面铺底 + 一张作品卡（名称 / 第 N 集 / 简介）+ 一句缓解等待的文案（"正在寻源与缓冲，通常 3 秒内开始"），大播放键压在下方而不是盖住简介；
  - 卡里**不再放一张小封面**（2026-10-30 删）：底衬就是同一张图，再放一次等于同一部作品出现两次封面。
- **弹幕默认关闭**：关时控件行里连输入框都不出现（关干净）；开时集齐透明度 / 字号 / 速度 / 屏蔽词 / 发送，控制权在播放器内的设置面板（**播放设置属于播放器，不属于全局设置**）；
- 顶部留一行浅色「原型示意 · 界面可交互，功能未真实实现」的说明，避免把演示当成品。
- 未实现的按钮**要么不可点、要么给明确提示**，不许点了没反应。

### 2.12 阅读器（覆盖层）

- 顶部：返回 / 章名 / **下载** / **加入作品区** / 目录 / 图·文模式切换 / 设置；
  - 下载与加入作品区**在阅读器里就能做**，不必退到详情页再操作一遍；
- 目录两级：**卷 → 话/章**，与详情页结构一致；**点卷只展开该卷的话，不改变当前阅读位置**；点具体话才跳转；
- 漫画：单页 / 双页 / 竖向滚动；小说：字号 / 行距（1.6 / 1.9 / 2.2）/ 字体（黑体 / 宋体）/ 版心宽（620 / 700 / 820）/ 背景（跟随主题 / 纸 / 羊皮 / 夜间）；
- 底部：上一话 / 进度 / 下一话；
- **阅读进度必须保存**：每次打开/翻页都记下"第 X 卷第 Y 话"，下次「继续阅读」回到该位置（作品区的卷进度与阅读器位置以阅读器为准，哪个更新用哪个）。
- **进度百分比口径（2026-10-30 明确）**：从本章开头到已读位置，**在本章内容里的百分比**（按 `.reader-body` 的滚动位置算），不是"第几章 / 总章数"。所以正文必须足够长能滚起来，短章不应显示 100%。
- **工具栏按钮对齐开源阅读器（KOReader / Foliate / 静读天下）**：目录 / 书签 / 笔记（划线） / 全文搜索 / 朗读 / 自动滚动；这些先做成按钮占位，实现列入 §9。

### 2.13 返回：先回来处，再回上级

**结论（2026-10-30 修正）**：返回的目标是**你真正从哪儿来**，不是「这一页在结构上属于谁」。

```
有来处（本次会话里真实走过的那一步）  → 回那一步，按钮写那一步的名字
没有来处（直接打开链接 / 刷新进这一页） → 回结构上的上级
```

- 反例（已修）：从**作品区**点进详情页，返回按钮写「返回首页 · 动漫」，按下去真去了首页 —— 来处是作品区，人却被送到另一个地方。
  现在从作品区进来，按钮就是「**返回作品区**」。
- 实现：一个 `backStack` 记每次真实跳转的地址；返回时弹出上一条并**不再压栈**（否则返回也变成前进）。
  栈空才退回结构上级。浏览器自带的返回也会移动 hash，栈里可能留下与当前相同的项，弹栈时跳过。
- 结构上级（栈空时）仍然是这张表，顺序不变：

```
首页（根）
 ├─ 分类页        → 返回X首页
 ├─ 功能页(排行榜/时间表/标签广场/…) → 返回X首页
 ├─ 作品详情      → 返回X首页（X = 作品所属分区）
 │    └─ 百科    → 返回详情
 ├─ 典藏
 │    └─ 系列页  → 返回典藏
 └─ 我的
      ├─ 下载中心 / 资源管理 / 设置 / 功能面板 → 返回我的
```

- **播放器 / 阅读器是详情的下一层**：从任意位置打开，退出时**落在该作品的详情页**（那是它的上一级）；
  从作品区点开的那次，退出后详情页压在作品区上面，于是再返回就回到作品区。
- 播放器 / 阅读器的地址用 `replaceState` 换，不新增历史：播放器是详情页的一层皮，不该在后退里多占一层。

### 2.14 地址即状态（2026-10-30 新增）

原型虽然是单页应用，但**每一个"看得见的状态"都该有地址**，否则刷新 / 分享 / 后退三件事全废。

| 地址 | 对应状态 |
| --- | --- |
| `#/aggregate?p=game` | 首页 · 游戏分区 |
| `#/shelf?p=music` | 作品区 · 我的音乐 |
| `#/detail/aot` | 作品详情 |
| `#/player/aot?ep=3` | 播放器（第 3 集） |
| `#/reader/frieren?vol=3&ch=2` | 阅读器（第 3 卷第 2 章） |
| `#/search?q=巨人&scope=anime` | 搜索结果（范围=动漫） |
| `#/mine/disk`、`#/mine/resource` | 磁盘管理、资源管理 |

- `#/player/*`、`#/reader/*` 的**底衬是详情页**：直接打开这条地址，关掉播放器就落在详情页，不会掉进空白。
- 地址不认识就**明确 404**，不静默回落到首页 —— 静默回落会让人以为链接是对的。
- 搜索框回车 = 把当前搜索变成一个可分享的地址（`#/search?q=…`）；输入过程中不发地址，避免历史里塞满每一个字符。

## 3. 数据模型要点

1. **分区独立**：五个分区的作品各自独立、互不重复（当前 78 部：动漫 19 / 游戏 14 / 漫画 14 / 轻小说 11 / 音乐 20，28 个系列；音乐共 131 首曲目，形态为单曲专辑 5 / OST 5 / 专辑 4 / 同人专辑 3 / 广播剧 3），代表作品要能体现"同一系列跨介质"。
2. **跨介质串联**：作品带 `series` 字段；`SERIES_NAMES` 给系列中文名。典藏 = 有 series 的系列集合；系列页 = 该 series 的全部成员。
3. **状态显式**：`status`（连载/完结）与 `form`（剧场版）必须是**真实字段**，不允许用"年份≥2023 就算连载"这类反推逻辑。
4. **卷结构**：漫画/小说 `volumes = [{n, name, chapters:[{n,title}]}]`；动漫 `episodes = [{n, sources:[...]}]`（**集数拼图**：作品→集→多源）。
5. **进度结构化**：`progress = { total, at, ch, chOfVol, pct, done }` —— `total` 由结构算出（集数/卷数），`at` 是读到第几集/卷，小说多一个 `ch`（第几章）。
   - **数据源只写"读到哪"**：作品区状态写成 `read:{at:108, ch:1}`，`progress` 由 `deriveProgress(w)` 派生，**不许手写百分比字符串**（旧的 `shelfProg` 文本已废弃）。
   - 百分比口径：动漫 `at/total`；漫画/小说 `(at-1 + ch/chOfVol)/total`，保留整数，夹在 1~~100。
   - 只认显式 `read.done` 才算已看完，**不许用"读到最后一集"反推已看完**；游戏恒为 `null`。
6. **封面接口**：`coverStyle(w)` / `coverInner(w)` —— 每部作品的 `w.cover` 由 `coverOf(id)` 统一绑定到 `assets/covers/<id>.jpg`（58 张真图，AniList + Steam CDN 抓取，见 `tools/fetch_covers.py`）；真图缺失时才回落 `coverArt(accent)` 渐变 + 首字水印。
7. **派生数据集中生成**：评分、热度（日/周/总）、更新时间、放送档期在 data.js 末尾统一生成，各页面不各算一套。
8. **来源字段（`og`）只有六种取值**，界面文案由 `originText(w)` 统一产出，**禁止**各页面自己拼"原作：漫画"这类半成品：

   | `og`   | 含义        | 界面文案        |
   | ------ | --------- | ----------- |
   | `原作`   | 本身就是原作    | `原作`        |
   | `原创`   | 动画原创企划    | `原创`        |
   | `漫画改`  | 改编自漫画     | `改编自 漫画`    |
   | `轻小说改` | 改编自轻小说    | `改编自 轻小说`   |
   | `游戏改`  | 改编自游戏     | `改编自 游戏`    |
   | `小说改`  | 改编自一般小说   | `改编自 小说`    |

   > 判定口诀：**只标一次**。是原作就只写"原作"，绝不出现"原作 · 改编自漫画"这种自相矛盾的组合。

9. **音乐是"专辑"，不是"曲"**：一条 `kind:'music'` 的数据 = 一张碟（单曲专辑/专辑/OST/同人专辑/广播剧），
   曲目在 `tracks:[{n,title,dur}]` 里，演唱者在 `artist`（多人用 ` / ` 分隔），`albumType` 是它的发行形态。
   - `countOf(w)` 对音乐返回**曲目数**；`totalUnitOf()` 返回「首」；
   - 总时长 `albumDur(w)` 由 `tracks[].dur`（`m:ss`）累加得来，**不许手写"43 分钟"这种死数字**；
   - 音乐 `og` 留空（见 §2.3.1 ⑦），`series` 只挂到已存在的系列（fate / aot / eva …），不新造系列。

10. **同名后缀只加在混合列表里**：跨介质同名的作品（Fate/Zero 有动画/漫画/小说三份）名字里才带「（漫画）」「（小说）」。
   - **分类页 / 系列页 / 搜索结果**（混合介质）→ 保留后缀，否则同一行里两个"Fate/Zero"分不清；
   - **作品区 / Hero / 详情页**（同一介质内）→ 去掉后缀，`w.name.replace(/（(漫画|小说|动漫)）$/,'')`。

11. **评分三字段，分属两轨**（§10）：
    - `score`（一位小数）+ `scoreSrc`（来源，如 `Bangumi`）+ `votes`（票数）——**媒体分，只读**，三者必须一起出现，缺 `votes` 就不许显示均分；
    - `myScore`（1–5 整数，存 `localStorage: acgn-my-score`）——**个人分**，只在本机，不参与任何排序、推荐、榜单；
    - **禁止**把两者加权成一个"综合分"，也禁止在 `myScore` 上存小数或半星。
12. **游戏用离散状态，不用百分比**：`gameInfo.status ∈ {在玩, 已通关, 想玩, 搁置}`；`progress` 对游戏恒为 `null`（§0.5 的定界）。
    界面只在两处引用 `status`：作品卡副信息行、作品区筛选项。
13. **音乐没有进度也没有状态**：只有 `albumType`（发行形态）。任何"看到哪 / 听完几成"的字段对音乐都是伪字段。

| 场景        | 动漫  | 漫画      | 轻小说     | 音乐     |
| --------- | --- | ------- | ------- | ------ |
| 总量（"全 N X"） | 集   | **卷**   | **卷**   | **首**  |

- 移动/窄屏：分区条与功能区允许换行，功能区降为每行 3 个，但不得留空位。

### 4.6 转场动效（2026-10-29 新增）

**五种导航动作 → 五条曲线。判断依据是"用户做了什么"，不是"渲染了哪个页面"。**

| 动作 | 触发场景 | `data-anim` | 动画 | 时长 |
| --- | --- | --- | --- | --- |
| 切底栏 | 首页 / 作品区 / 典藏 / 我的 互跳 | `tab` | 淡入 + 上移 12px | 260ms |
| 换分区（向右） | 动漫 → 游戏 → 漫画 → … | `part-r` | 淡入 + 从右进 38px | 340ms |
| 换分区（向左） | … → 漫画 → 游戏 → 动漫 | `part-l` | 淡入 + 从左进 38px | 340ms |
| 换主体 | 切「我的追番 / 我的游戏」 | `swap` | 只 `.page-body` 淡入 + 上移 12px | 220ms |
| 换一张推荐 | 点「换一个」 | —（直接换 DOM） | 只 `.hero` 淡入 + 上移 10px | 320ms |
| 进子页 | 全部 / 排行榜 / 详情 / 百科 | `push` | 淡入 + 从右进 32px + 放大 .992→1 | 320ms |
| 退回 | 返回上一页 | `pop` | 淡入 + 从左进 26px | 300ms |
| 原地重绘 | 切筛选 / 切排序 | `same` | 无 | — |

**作用域（v2.8 的核心）**：`part-r` / `part-l` / `swap` **不作用在 `.view` 上**，而是作用在 `.page-body` 上。
`.page-body` 是"每页会变的那一块"，页面级的条（`.agg-toolbar` 分区条、`.shelf-tabs`）留在它外面。
`.view[data-anim="part-r"]` 自身是 `animation:none`，否则整页（含分区条）会一起横滑。
只有 `tab` / `push` / `pop` 这三种"整页都换"的动作，才把动画给 `.view`。

**六条硬规矩**

1. **返回必须比进入快**：`pop` 300ms < `push` 320ms。返回是"我已经知道要去哪"，多等一帧都嫌慢。
2. **同级跳转动作要小**：底栏切 tab 只上移 12px，**不横滑**——横滑意味着"换了一层"，而 tab 之间是平级的。
3. **首页换分区用横滑，方向跟分区条排列一致**：点右边的分区，内容从右边进来；方向反了会让人以为自己点错。
4. **首屏不播动画**：打开就淡入，等于让人先看 300ms 的白屏才见到首页。
5. **原地重绘一律 `animation:none`**：切个筛选整页重新淡入，看起来像页面崩了重载。
6. **必须尊重 `prefers-reduced-motion`**：系统要求减少动效时，所有时长压到 0.001ms。
7. **动画不许跨层**：分区条 / tab 条这类"只是换个高亮"的控件，永远不参与内容动画。
8. **局部变化就别整页重渲染**：「换一个」只替换 `.hero`，「追番」只换按钮文字——DOM 重建一次，
   页面里所有带 `animation` 的元素就会重播一遍入场。

**实现上会踩的三个坑**（每一个都会让"动画看起来根本没做"）

- **`--ease` 不能喂给 `animation`**。它的值是 `220ms cubic-bezier(...)`（时长 + 曲线合体），只适合 `transition`。
  写进 `animation:viewIn .35s var(--ease)` 会被解析成「.35s 动画 + 220ms delay」——
  页面先空等 220ms 再淡入，手感就是"点了没反应，然后突然出现"。给 animation 用纯曲线的 `--ease-out`。
- **同一个元素上换 `data-anim` 的值不会重播动画**：属性变了，但动画名和起止状态没重算。
  必须 `removeAttribute` → 强制一次 `offsetWidth` → 再挂回去。
- **路由会被触发两次**：`navigate()` 同步调一次 `route()`，浏览器随后还会再派发一次 `hashchange`。
  第二次重绘会带着 `no-anim` 把刚起的动画直接掐掉。用路由签名去重（签名相同就 return），
  同地址再点一次走 `route(true)` 强制重绘。**签名要包含 `k / c / tag / a` 等全部查询参数**——
  只看 `view/id/p` 的话，功能页之间互切（`k` 不同）会被误判成原地重绘。

```

  → 值得反复看 → 典藏（系列卡）→ 系列页（内容地图）
```

```
游戏分区 → 新游推荐/即将发售 → 详情（游戏信息）→ 启动游戏
  → 引擎未装 → 下载插件 → 即点即玩 → 记录时长/成就
```

## 8. 评审方法（每次改完都要过一遍）

对每个界面依次问四句：

1. **这个页面是用来做什么的？**（一句话说不清 = 结构有问题）
2. **页面上的每块信息，用户在这里需要吗？**（不需要 = 无效信息，删）
3. **这个功能在别处是不是已经有了？**（有 = 重复，二选一）
4. **用户在这个页面要做的事，能不能在这里做完？**（不能 = 缺闭环，补或迁移）

> 判定顺序：先砍（无效/重复），再补（缺闭环），最后才调样式。

### 9.1 标签广场改版建议（R51 答复）

现状问题：**只有"名字 + 数字"两列信息，点进去还是分类页**，所以它既不像是"发现入口"，也不像是"导航"，只能当装饰。五个建议，按性价比排：

1. **标签卡带缩略图**（最有效）：每个标签后面拼 3–4 张该题材的代表封面（错位叠放），标签就从"词"变成"一片内容"。成本低——封面数据已经有了。
2. **加热度条 / 趋势箭头**：`战斗 9 ↑2` 比 `战斗 9` 多一层"最近在涨"的信息，用户才知道为什么要现在点。趋势值可以先用"近 7 天新增收录数"演示。
3. **分组从"热门/常规/长尾"改成"情绪 / 设定 / 制作"三类**：现在三档其实是同一个维度的分档，扫起来是"大中小"，没有语义；按语义分组才能帮人找"我想看那种"。（`治愈/催泪/黑暗` 属情绪，`异世界/校园/机战` 属设定，`漫画改/原创/剧场版` 属制作。）
4. **顶部加"为你推荐 3 个标签"**：一句话说明推荐理由（"你看的 5 部里 4 部带这个标签"），把广场从浏览变成引导。
5. **点标签不直接跳分类页，先在原地展开前 6 部作品**（横向一排封面 + "查看全部 →"）：少一次跳转，也让广场自己产生内容。这一条和第 1 条配套做效果最好。

不做：标签云随机排布（球形/螺旋）、标签关注与订阅、用户自建标签——数据量和运营都撑不住。

## 10. 评分与评论机制（按伦理设计 · 备选方案，暂未采用）

> **状态：未采用（2026-10-30 决定）。** 本节保留为备选方案，等真正要接社区时再回来定案；
> 在决定之前，产品里**不出现任何打分入口**——详情页只显示媒体分与样本数（§2.8），
> 评测/攻略列表不显示星级（§7 第 93 条）。**别把本节当成已定案的口径去实现。**

这一节回答一个问题：**为什么同类软件的评分和评论越做越没人信，而我们要怎么把它做成"真的有用"。**
不是"加点防刷"，而是先承认评分是一种**社会行为**——它同时是"我表达"和"影响别人"，两者都有伦理后果。

### 10.1 先诊断：五个病根

| # | 病根 | 具体表现 | 后果 |
| -- | -- | -- | -- |
| 1 | **一个总分把不同人群平均掉** | 粉丝、路人、原作党、首集党、倍速党全倒进同一个漏斗 | 分数只反映"最积极的那群人"，与作品质量弱相关 |
| 2 | **评分权绑定"看完"** | "只有看完才能评"看着合理，实则把弃坑者全部排除 | **幸存者偏差**：难看的作品反而只有喜欢的人打分，分数系统性虚高 |
| 3 | **虚假精度** | `8.73` `9.1` 挂在封面角上，不带票数、不带来源、不带时间 | 用户以为是共识，其实是 40 个人的平均 |
| 4 | **分数被商业与流量绑架** | 新番开播冲榜、首周刷分、开分日"谷子" | 分数变成营销位，长期读者不再信任 |
| 5 | **评论区被"热评"寡头化** | 按赞数排序，前 3 条决定一部作品的口碑；剧透无治理；异议被围攻 | 沉默螺旋：想说"我觉得一般"的人干脆不说 |

一句话概括：**现在的评分回答的是"大家希望别人怎么想"，不是"我该怎么花这两小时"。**

### 10.2 三条不能让的伦理底线

1. **表达权**：只要真的消费过（看了一集、玩了一小时、读了一卷），就有权评价——**包括"我弃了"**。
2. **不误导**：任何分数都必须能回答三件事——**谁在评、多少人、什么时候**。答不出来的分数不许显示。
3. **不伤害**：剧透、人身攻击、群体围攻是内容治理问题，不是"社区氛围"问题；用户数据可撤回，删了就是删了。

在这三条之下才谈产品策略。

### 10.3 评分机制：分两轨，绝不合成一个数

| 规则 | 做法 | 为什么 |
| -- | -- | -- |
| **双轨制** | **媒体分**（聚合自 Bangumi / AniList，只读，标来源与票数）与**我的分**（5 星，仅本机）分两处展示 | 两个数回答两个问题："大家怎么看"和"我怎么看"。混成一个综合分，两个问题都答不清 |
| **弃坑也算** | 允许"看到第 N 集就弃"，单独成档统计，**不与看完的人混算** | 这是治第 2 号病根的唯一办法：不给弃坑者话筒，分数必然虚高 |
| **样本量门槛** | 票数 < 300 时只写"样本不足"，不显示均分；≥300 显示一位小数 + `N 人` | 精度必须与证据匹配。`8.7` 配 12 个人，是把噪声包装成结论 |
| **时间分层** | 首播前 7 天的分**单独一档**（"开播口碑"），完结后另有"完结口碑" | 首集党与补番党评价的不是同一个东西（作画、节奏、结局） |
| **一人一票、权重封顶** | 单人最多 1 票；不做"资深用户 ×3"这类加权 | 加权一定被钻：谁算资深？最后变成小圈子定价 |
| **剔除公开** | 刷分/异常样本剔除**数量**对所有人可见（不公开是谁） | 透明度是唯一的防腐剂；"我们删了 1,204 条异常票"比"我们严格防刷"可信 |
| **可撤回** | 用户删除评分即生效，不留历史快照 | 数据最小化；也避免"三年前的 2 星"永远钉在个人画像上 |
| **均分不进排序** | 排行榜按**播放/在读热度**排，不按均分排 | 均分排序奖励两极（神作/烂作都靠争议涨分）、惩罚"稳但平庸"的作品 |
| **不做人格分** | 没有"用户信誉分""评分可信度"这类把人也打个分的机制 | 评价作品是权利，不该变成需要攒积分的资格 |

**关于个人分：为什么是 5 星而不是 10 分制**——10 分制会让用户在小数上做无意义区分（8 分还是 8.5？），
而 5 星的分辨率刚好够"喜欢/一般/不喜欢"三档再细分两档；**也不显示 4.5 星**（半星同样是无意义的精度）。

### 10.4 评论机制：为"读的人"设计，不为"写的人"排名

| 问题 | 机制 | 说明 |
| -- | -- | -- |
| **剧透** | 三段可见性：`无剧透` / `轻微（前 3 集）` / `深度（全篇）`；**作者自标 + 读者标记**，≥3 人标记自动折叠 | 靠"禁止剧透"没用，靠"分级 + 折叠"才有用。折叠不删除，作者可申诉 |
| **热评寡头** | 默认排序 = **时间**；"最有帮助"要读者**主动切换**；**不公开点赞数** | 赞数是竞争性指标，会把写作动机从"说清楚"变成"讨好" |
| **回音室** | 每部作品下有「不同意见」入口：列出与**你自己评分**差 ≥2 星的评论各一条 | 让人看见"和我一样喜欢这部的人，也有人讨厌它"，比推荐同温层更有价值 |
| **情绪泄洪** | 短评结构化：`一句话结论` + `一个提醒`（"前 3 集慢热""第 8 集作画崩"）+ 可选长文 | 把"难看死了"导向"我为什么看不下去"，评论才对下一个人有用 |
| **围攻** | 三类举报：剧透未标 / 人身攻击 / 广告；处理结果**回告举报人** | 举报没有反馈，等于没有举报 |
| **抢首评** | 新作品 24 小时内的评论不进"最新"，先入"待读"池 | "沙发"是纯噪声，且会挤掉真正看完的人 |
| **商业内容** | 一律标注"含推广"；同一账号对同一作品**只能有一条**评论（可编辑，留痕） | 刷评的经济动机主要来自推广，堵住这一条最有效 |

### 10.5 怎么才算"真的带来作用"

评分和评论不该是"广场"，而该是**决策辅助**。落到产品上只有三件事：

1. **让分数可被质疑**：任何均分旁边永远有"多少人、什么时候、谁在评"。用户学会看样本量，比我们做十个防刷算法更有用。
2. **让评论可被检索**：结构化短评 + 剧透分级 = 你可以只看"看到第 5 集的人怎么说"。这才是评论区的原始需求。
3. **让个人偏好可被回看**：我的评分不是为了给别人看，而是为了**认识自己**——"我给 5 星的 12 部里有 9 部是慢热型"这种洞察，比任何总分都更能改善下一次选择。
   （这条对应"观看统计"页的后续扩展，见 §9）

**反过来说，三件事明确不做**：不做综合总分、不做"神作 / 粪作"标签、不做"猜你喜欢"式的评分预测。
一旦分数参与推荐，就会滑向"因为分高所以看、因为看了所以打高分"的自我实现循环。

### 10.7 本节的红线（禁止复活）

- **一个综合总分**（媒体分 + 用户分 + 你的分 加权成一个数）；
- **看完才能评**（会系统性抬高分数）；
- **显示两位小数的均分**、**不带样本量的均分**；
- **热评榜**、**公开点赞数**、**评论者的"被赞总数"**；
- **用户信誉分 / 评分权重等级**；
- **"神作 / 粪作 / 年度最佳"这类由分数直接生成的头衔**。
